# 벤치마크

## 내장 데이터셋

| 이름 | 유형 | 규모 | 내용 |
|---|---|---|---|
| `ko_en_retrieval_mini` | retrieval | 쿼리 30 / 문서 33 | 한국어 12, 영어 10, ko→en 4, en→ko 4. 김치↔된장, 지하철↔버스, 오로라↔태양광 같은 헷갈리는 문서 포함 |
| `ko_sts_mini` | sts | 문장쌍 24 | 한국어·영어·교차언어 쌍, 0~5점 정답 |

미니 데이터셋은 **빠른 동작 확인과 상대 비교용**입니다. 규모가 작아 상위 모델은 만점 가까이 나와 차이가 잘 드러나지 않을 수 있습니다. 실제 서비스용 모델을 고를 때는 자기 도메인 데이터로 만든 데이터셋을 업로드해 평가하세요.

## 지표

**검색 (retrieval)** — 쿼리 임베딩(query 역할)과 문서 임베딩(document 역할)의 코사인 유사도 순으로 정렬합니다.

- `recall@k`: 상위 k개 안에 든 정답 비율 (정답이 여러 개면 나눠서 계산)
- `mrr@10`: 첫 정답 순위의 역수 평균 (10위 밖이면 0)
- `ndcg@10`: 순위 가중 정답 점수 (대표 지표)

쿼리에 `lang`(또는 `group`) 필드가 있으면 그룹별 지표를 따로 보여 줍니다.

**STS** — 두 문장(plain 역할) 임베딩의 코사인 유사도와 정답 점수의 상관계수.

- `spearman` (대표 지표, 순위 상관), `pearson` (선형 상관)

함께 기록하는 값: 임베딩 차원, 인코딩 시간, 처리량(texts/s), 로드 시간, 프롬프트 적용 내역, 경고.

## 신뢰구간과 순위 비교

평가 질문이 수십 개뿐이면 지표 몇 %p 차이는 우연일 수 있습니다. 결과마다 다음을 함께 계산합니다(`app/services/stats.py`).

- **95% 신뢰구간** (`ci`): 질문(STS 는 문장쌍)을 복원 추출로 1,000번 다시 뽑아 지표를 계산한 분포의 2.5~97.5 백분위. 검색은 모든 지표, STS 는 spearman·pearson.
- **1위 대비 짝지은 비교** (`vs_best`): 같은 질문 묶음을 두 모델에 함께 적용해 차이의 분포를 구합니다. 질문 난이도 차이가 상쇄되어 각자의 구간을 비교하는 것보다 예민합니다. 차이의 95% 구간이 0을 포함하지 않으면 **유의한 차이**, 포함하면 **차이 불확실**입니다(`p` = 양측 부트스트랩 p값).

실측(내장 데이터셋, 3개 모델):

| 데이터셋 | 1위 | 2·3위와의 차이 | 판정 |
|---|---|---|---|
| ko_en_retrieval_mini (질문 30개) | EmbeddingGemma 2 nDCG 100.0 | KURE −2.2%p, BGE-M3 −2.3%p (p=0.25) | 차이 불확실 |
| ko_sts_mini (문장쌍 24개) | BGE-M3 spearman 0.671 [0.26, 0.92] | KURE −0.005, EmbeddingGemma 2 −0.145 (p=0.23) | 차이 불확실 |

내장 데이터셋은 동작 확인용으로 작아서 순위를 가르기에 부족합니다. 모델을 고를 때는 실제 문서로 만든 평가 세트나 공개 벤치마크처럼 수백 개 이상의 질문으로 비교하세요.

## 옵션

- **Matryoshka 차원**: 선택한 차원으로 잘라 정규화합니다(`truncate_dim`). 모델 차원 이상이면 무시합니다. MRL로 학습되지 않은 모델은 성능이 크게 떨어질 수 있습니다.
- **Matryoshka 차원 스윕**: 켜면 전체 차원으로 **한 번만** 인코딩한 뒤 입력한 차원들(기본 2048,1024,768,512,256,128,64)로 잘라 다시 정규화하고 각각 평가합니다. 추가 인코딩이 없어 거의 공짜입니다. 모델 차원보다 큰 값은 건너뜁니다. 켜면 단일 "Matryoshka 차원" 선택은 무시됩니다. 결과는 "차원별 성능" 차트와 표로 나옵니다.
- **배치 크기**: 기본값 `DEFAULT_BATCH_SIZE`(16). 메모리가 부족하면 줄이세요.
- **평가 후 언로드**: 큰 모델 여러 개를 비교할 때 메모리를 아낍니다.

## 공개 한국어 벤치마크

벤치마크 화면의 **공개 한국어 벤치마크 가져오기**에서 Hugging Face Hub 의 MTEB 형식(parquet) 데이터를 내려받아 데이터셋(`pub_*`)으로 추가합니다(`app/services/public_benchmarks.py`, 파일은 HF 캐시에 저장).

| 키 | 유형 | 원본 규모 | 내용 | 라이선스 |
|---|---|---|---|---|
| `autorag_ko` | retrieval | 질문 114 · 문서 720 | 금융·공공·의료·법률·커머스 PDF 문단과 업무형 질문 (RAG 에 가장 가까움) | MIT |
| `ko_strategyqa` | retrieval | 질문 592 · 문서 9,251 | 여러 문단을 이어 추론하는 상식 질문 (번역) | 원본 StrategyQA MIT |
| `publichealth_ko` | retrieval | 질문 77 · 문서 77 | 공중보건 FAQ | CC BY-NC-SA 3.0 |
| `xpqa_ko` | retrieval | 질문 654 · 문서 889 | 쇼핑몰 상품 질문 → 상품 정보·리뷰 | CDLA-Sharing 1.0 |
| `korsts` | sts | 문장쌍 1,376 | STS-B 한국어 번역 (test) | CC BY-SA 4.0 |
| `klue_sts` | sts | 문장쌍 519 | 처음부터 한국어로 만든 STS (validation) | CC BY-SA 4.0 |

- **표본**: 최대 질문 수·최대 문서 수를 넘으면 질문을 무작위(seed 고정)로 뽑고, 그 질문들의 정답 문서는 모두 넣은 뒤 나머지를 무작위 방해 문서로 채웁니다. 원본 전체로 잰 MTEB 점수와 절대값은 다르지만 모델 간 비교에는 쓸 수 있습니다. 데이터셋 설명에 출처·라이선스·표본 조건이 기록됩니다.
- 문서 본문은 4,000자에서 자릅니다. 0점 qrels 는 정답으로 보지 않습니다.
- API: `GET /api/public-benchmarks`, `POST /api/public-benchmarks/{key}/import {"max_queries": 300, "max_corpus": 3000, "seed": 0}` → 작업.

## 사용자 데이터셋 형식

```json
{
  "name": "my_faq",
  "type": "retrieval",
  "title": "사내 FAQ 검색",
  "description": "선택",
  "corpus": [
    {"id": "d1", "title": "선택", "text": "문서 본문"}
  ],
  "queries": [
    {"id": "q1", "text": "질문", "relevant": ["d1"], "lang": "ko"}
  ]
}
```

```json
{
  "name": "my_sts",
  "type": "sts",
  "pairs": [{"s1": "문장 1", "s2": "문장 2", "score": 4.5}]
}
```

- `name`은 영문/숫자/`_`/`-` 1~64자, 내장 데이터셋 이름과 겹치면 안 됩니다.
- 문서에 `title`이 있으면 `"{title}\n{text}"`로 합쳐 인코딩합니다.
- 업로드한 파일은 `data/datasets/`에 저장되고 UI에서 삭제할 수 있습니다.
