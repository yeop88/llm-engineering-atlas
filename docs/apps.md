# 의미 기반 응용

메뉴의 **응용**에서 임베딩(텍스트의 의미 벡터)으로 만들 수 있는 기능을 바로 써 볼 수 있습니다. 시맨틱 검색은 [문서 검색](rag.md), 유사도 행렬·임베딩 지도는 플레이그라운드에 있으므로 여기서는 다루지 않습니다.

## 공통

- **입력 소스**
  - **직접 입력**: 한 줄에 하나. 라벨이 필요한 기능(분류 학습 등)은 `[라벨] 텍스트` 형식. 기능마다 **예시 데이터**를 고를 수 있습니다.
  - **문서 검색 컬렉션**: 컬렉션의 문서(제목 + 앞부분 2,000자) 또는 청크 세트의 청크를 그대로 씁니다.
- **임베딩 모델**: 카탈로그의 임베딩 모델과 Matryoshka 차원을 고릅니다.
- **임베딩 캐시**: (모델, 역할, 차원, 텍스트)가 같으면 다시 계산하지 않습니다(메모리, 최대 10만 개). 같은 데이터로 설정만 바꿔 다시 실행하면 즉시 끝납니다. `GET /api/apps/cache` 로 적중률을 볼 수 있습니다.
- 모든 실행은 백그라운드 작업으로 돌고 진행률이 표시되며, **이력**에 `app_*` 종류로 남습니다.

## 콘텐츠 추천

뉴스·상품·강의·사내 문서처럼 **아이템 목록에서 취향에 맞는 것을 고르는** 기능입니다.

1. 추천 대상 아이템을 불러와 👍(좋아요) / 👎(싫어요)를 누르거나 **관심사 문장**을 적습니다.
2. 취향 벡터를 만듭니다: `정규화(평균(좋아요) − 0.5 × 평균(싫어요) + 관심사)`
3. 아이템마다 취향 벡터와의 코사인 유사도(관련도)를 계산하고, **MMR**로 고릅니다.
   `점수 = (1 − 다양성) × 관련도 − 다양성 × (이미 고른 것과의 최대 유사도)`
4. 결과마다 **추천 이유**(가장 비슷한 좋아요 아이템과 유사도)를 보여 줍니다.

| 설정 | 설명 |
|---|---|
| 다양성 (기본 0.15) | 0 이면 관련도 순서 그대로, 올릴수록 서로 비슷한 아이템이 몰리지 않게 골고루 고릅니다. 임베딩 모델은 관계없는 문장끼리도 유사도가 0.6 안팎으로 나오는 경우가 많아, 0.3 이상이면 관련도가 크게 떨어질 수 있습니다. |
| 추천끼리 평균 유사도 | 결과 아이템끼리의 평균 유사도. 낮을수록 다양합니다. |

실측(EmbeddingGemma 2, 예시 기사 30건): 김치·된장찌개 기사에 좋아요 → 비빔밥·통닭 등 요리 기사와 "가이세키 요리" 료칸 여행 기사가 상위. 관심사 "주말에 갈 만한 산과 단풍 여행지" → 설악산·내장산 단풍 → 한라산 등반 순.

API: `POST /api/apps/recommend {"model_id", "source", "liked": [키], "disliked": [키], "interest", "top_k", "diversity"}` → 작업. 아이템 키는 `POST /api/apps/items {"source"}` 로 확인합니다(직접 입력은 줄 번호, 컬렉션은 `d{문서 id}` / `c{청크 id}`).

## 텍스트 분류

감성분석, 고객·AS 문의 자동 분류(라우팅), 스팸 판별처럼 **정해진 라벨로 나누는** 기능입니다.

| 방식 | 필요한 것 | 동작 |
|---|---|---|
| **제로샷** | 라벨과 설명 (`긍정: 제품에 만족하고 칭찬하는 리뷰`) | 텍스트와 "라벨: 설명" 문장의 유사도로 라벨을 고름. 학습 데이터 없이 바로 사용 |
| **퓨샷 학습 · 로지스틱 회귀** (권장) | 라벨 붙은 예시 (`[라벨] 텍스트`) | 임베딩 위에 선형 분류기 학습. 예시가 수십 개 이상일 때 가장 정확 |
| **퓨샷 학습 · 중심점** | 라벨당 2~5개부터 | 라벨별 평균 벡터와 가장 가까운 라벨 |
| **퓨샷 학습 · kNN** | 라벨 붙은 예시 | 가장 가까운 예시 k 개의 투표(가까울수록 큰 가중치). 한 라벨 안에 여러 유형이 섞여 있을 때 유리 |

- **평가**: 라벨 비율을 유지하는 5겹 교차검증으로 정확도·Macro F1·라벨별 정밀도/재현율/F1·**혼동행렬**·틀린 예시를 보여 줍니다. 제로샷도 입력에 정답 라벨이 있으면 같은 지표를 계산합니다.
- **저장·예측**: "전체 데이터로 학습해 저장"을 켜면 분류기를 저장합니다(`data/app_models/{id}.joblib`). 저장된 분류기 탭에서 바로 예측하거나 API 로 호출합니다.

  ```bash
  curl -X POST http://127.0.0.1:8000/api/apps/classifiers/7/predict -H "Content-Type: application/json" -d '{"texts": ["택배가 아직 안 왔어요"]}'
  ```
- **작업 프롬프트**: 모델에 분류용 프롬프트가 정의돼 있으면(예: EmbeddingGemma 의 `Classification`) 자동으로 씁니다.

### 실측 (5겹 교차검증, CPU)

| 데이터 | 방법 | EmbeddingGemma 2 | BGE-M3 |
|---|---|---|---|
| 상품 리뷰 감성 45건 (긍정·부정·중립) | 제로샷 | 80.0% | 73.3% |
| | 학습 · 중심점 | 86.7% | **95.6%** |
| | 학습 · 로지스틱 회귀 | 84.4% | **95.6%** |
| 고객·AS 문의 50건 (5개 부서) | 제로샷 | 88.0% | **90.0%** |
| | 학습 · 로지스틱 회귀 | 84.0% | 84.0% |

- EmbeddingGemma 2 는 분류 프롬프트 없이 인코딩하면 감성 정확도가 60% 에 그쳤고, `Classification` 프롬프트를 쓰자 84~87% 로 올랐습니다. 모델에 정의된 작업 프롬프트가 성능에 큰 영향을 줍니다.
- 문의 분류에서 공통으로 틀린 예("배송지를 회사 주소로 바꾸고 싶은데" → 계정, "송장번호가 조회되지 않습니다" → 계정)는 라벨 경계가 애매한 경우입니다. 실제 서비스에서는 이런 예시를 더 넣거나 라벨 정의를 다듬습니다.
- 예시가 50건 정도로 적을 때는 제로샷이 학습보다 나을 수도 있습니다. 데이터가 쌓이면 학습 방식이 유리해집니다.

API: `POST /api/apps/classify/zero-shot {"model_id", "source", "labels": [{"name", "description"}]}`, `POST /api/apps/classify/train {"model_id", "source", "method": "logreg"|"centroid"|"knn", "k", "save", "name"}` → 작업. `POST /api/apps/classifiers/{id}/predict {"texts"}` → 즉시 응답. `GET /api/apps/models?kind=classifier`, `DELETE /api/apps/models/{id}`.

## 클러스터링

비슷한 의미의 텍스트끼리 묶어 **주제를 발굴**합니다. 고객 문의·리뷰·VOC 주제 분석, 문서 군집화, 같은 이슈 묶기에 씁니다.

| 방법 | 동작 | 언제 |
|---|---|---|
| **K-means** | 정한 개수로 나눔. 개수를 비우면 2~최대 사이에서 **실루엣 점수**가 가장 높은 개수를 자동 선택 | 대부분의 경우 |
| **계층 (평균 연결)** | 가까운 것부터 합쳐 나무를 만든 뒤 개수에서 자름 (코사인 거리) | 군집 크기가 고르지 않을 때 |
| **HDBSCAN** | 밀도가 높은 곳만 군집으로, 나머지는 **노이즈**로 분리. 개수 지정 불필요 | 데이터가 많고 잡음을 걸러내고 싶을 때 |

- **군집 키워드**: 군집을 한 문서로 보고 TF-IDF 를 매기는 c-TF-IDF 로, 그 군집에 유독 많이 나오는 **명사**(Kiwi 형태소)를 뽑습니다.
- **대표 문장**: 군집 중심과 가장 가까운 3개. **응집도**는 군집 안 텍스트와 중심의 평균 유사도입니다.
- **정답과 비교**: 입력에 라벨이 있으면 **ARI**(조정 랜드 지수, 1 = 완전 일치, 0 = 우연 수준)와 **순도**(각 군집의 다수 라벨 비율)를 계산합니다(노이즈 제외).
- **군집 지도**: PCA 2D. 군집이 4개 이상이면 색으로 구분되지 않으므로 모두 회색으로 그리고, 군집 카드나 점을 누르면 그 군집만 강조합니다. 결과는 CSV 로 내려받습니다.
- 모델에 군집용 프롬프트가 있으면(예: EmbeddingGemma 의 `Clustering`) 자동으로 씁니다.

### 실측 (K-means, 군집 수 = 정답 라벨 수)

| 데이터 | EmbeddingGemma 2 | BGE-M3 |
|---|---|---|
| 기사 30건 (6개 분야) | **ARI 0.91 · 순도 96.7%** | ARI 0.28 · 순도 63.3% |
| 고객·AS 문의 50건 (5개 부서) | **ARI 0.47 · 순도 74%** | ARI 0.32 · 순도 66% |

- 같은 모델이라도 분류와 군집화 성능은 다릅니다. BGE-M3 는 감성 분류에서 앞섰지만 군집화에서는 EmbeddingGemma 2(군집용 프롬프트 사용)가 크게 앞섰습니다. 쓰려는 작업으로 직접 비교하세요.
- 실루엣 자동 선택은 짧은 문장에서 군집 수를 적게 고르는 경향이 있습니다(문의 50건 → 2~4개). 기대하는 주제 수가 있으면 직접 지정하세요.
- HDBSCAN 은 짧고 다양한 텍스트 50건 정도에서는 대부분을 노이즈로 둡니다. 수백 건 이상에서 유용합니다.

API: `POST /api/apps/cluster {"model_id", "source", "method": "kmeans"|"agglomerative"|"hdbscan", "k": null, "k_max": 10, "min_cluster_size": 5}` → 작업.

## 중복·표절 검사

### 중복 제거

의미가 거의 같은 텍스트를 묶어 **하나만 남깁니다**. FAQ·문의 이력 정리, 학습 데이터 중복 제거, 같은 공지·게시글 반복 감지에 씁니다.

- **대표(리더) 방식 그룹화**: 앞에서부터 아직 그룹이 없는 항목을 대표로 삼고, 대표와 **직접** 유사도가 임계값 이상인 항목만 같은 그룹에 넣습니다. 쌍을 계속 이어 붙이는 방식(A≈B, B≈C → A≈C)은 관계없는 항목이 연쇄로 한 그룹이 되기 쉬워 쓰지 않습니다.
- **남길 것**: 먼저 나온 것 / 가장 긴 것. 나머지는 글자 일치도(문자 3-gram Jaccard)가 0.8 이상이면 **완전 중복**, 아니면 **의역**으로 표시합니다.
- **유사도 분포**: 각 텍스트와 가장 가까운 다른 텍스트의 유사도 분포(하위 10%·중앙값·상위 10%·히스토그램)를 함께 보여 줍니다. 모델마다 분포가 크게 달라 임계값을 정하는 근거로 씁니다.
- 결과에서 중복을 뺀 목록을 텍스트 파일로 내려받습니다. 큰 입력도 블록 단위로 유사도를 계산해 메모리를 넘지 않습니다.

### 표절 검사

검사할 글을 문장 단위로 나눠(Kiwi, 줄바꿈은 항상 경계) 참고 문서의 모든 문장과 비교합니다. 참고 문서는 직접 입력하거나 **문서 검색 컬렉션**을 그대로 씁니다(문장 2만 개까지).

| 판정 | 조건 |
|---|---|
| **복사** | 의미 유사도 ≥ 임계값 이고 글자 일치도 ≥ 복사 기준(기본 0.6) |
| **의역** | 의미 유사도 ≥ 임계값(기본 0.85) 이지만 글자는 다름 |
| **독창** | 그 외 |

표절 의심 비율은 글자 수 기준이며, 문장에 마우스를 올리면 가장 비슷한 원문과 점수가, 아래에는 출처별 문장·글자 수가 나옵니다.

### 실측 (예시 데이터)

| | EmbeddingGemma 2 | BGE-M3 |
|---|---|---|
| FAQ 30건 — 정답 4그룹(비밀번호·환불·배송지·주문 취소)을 찾는 임계값 | **0.90** | **0.80** |
| 보고서 표절 — 복사 1문장 | 찾음 | 찾음 |
| 보고서 표절 — 의역 2문장 | **둘 다 찾음** (0.94, 0.95) | 하나 놓침 (0.839) |
| 보고서 표절 — 독창 문장의 최고 유사도 | 0.81~0.84 (임계값에 가까움) | 약 0.5 (여유 큼) |

- **임계값은 모델에 따라 다릅니다.** EmbeddingGemma 2 는 관계없는 문장끼리도 0.8 안팎이라 0.85 이하로 내리면 그룹이 커지고, BGE-M3 는 0.8 에서도 정확합니다. 새 데이터·모델에서는 분포를 먼저 보고 중앙값보다 충분히 높게 잡으세요.
- 표절 검사에서 EmbeddingGemma 2 는 의역을 잘 잡지만 독창 문장과의 간격이 좁고, BGE-M3 는 반대입니다. 놓치지 않는 것이 중요하면 전자, 오탐이 적어야 하면 후자가 낫습니다.

API: `POST /api/apps/dedup {"model_id", "source", "threshold": 0.92, "keep": "first"|"longest"}`, `POST /api/apps/plagiarism {"model_id", "suspect", "reference": {...}, "threshold": 0.85, "copy_lex": 0.6}` → 작업.
