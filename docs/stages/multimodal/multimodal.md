# 멀티모달 임베딩

## 지원 모델 (카탈로그 기준)

| 모델 | 모달리티 | 비고 |
|---|---|---|
| google/embeddinggemma-2 | 텍스트·이미지·오디오·비디오 | 768d, MRL 512/256/128. 텍스트 270M + 비전 170M + 오디오 300M |
| Qwen/Qwen3-VL-Embedding-2B / 8B | 텍스트·이미지·비디오 | 2B는 CPU에서도 사용 가능, 8B는 GPU 권장 |
| jinaai/jina-embeddings-v5-omni-small | 텍스트·이미지 | CC-BY-NC-4.0 (비상업) |
| sentence-transformers/clip-ViT-B-32, clip-ViT-L-14 | 텍스트·이미지 | 고전 베이스라인. 텍스트 77토큰, 영어 위주 |

UI의 **멀티모달** 화면은 modalities에 `text` 외 항목이 있는 모델만 보여 줍니다. 다른 모델을 쓰려면 모델 상세 화면에서 모달리티에 `image`를 추가하세요.

## EmbeddingGemma 2 프로필

| 프로필 | 로드 kwargs | 로드되는 파라미터 |
|---|---|---|
| text (기본) | `{"config_kwargs": {"vision_config": null, "audio_config": null}}` | ~270M |
| multimodal | `{"config_kwargs": {"audio_config": null}}` | ~440M (텍스트+비전) |

오디오까지 쓰려면 모델 상세 화면에서 "로드 kwargs - 멀티모달"을 `{}`로 바꾸면 전체(~740M)를 로드합니다. 같은 체크포인트이므로 텍스트로 만든 임베딩과 이미지 임베딩을 바로 비교할 수 있습니다.

입력 형식: EmbeddingGemma 2는 `{"image": PIL.Image}` 딕셔너리, CLIP은 PIL 이미지를 그대로 받습니다. 앱이 두 형식을 차례로 시도합니다.

## 실측 (CPU, Ryzen 16스레드, fp32)

생성한 테스트 이미지 5장(노을 바다, 빨간 원, 풀밭, 달 뜬 밤하늘, 파란 사각형)으로 측정한 결과입니다.

| 쿼리 | CLIP ViT-B/32 1위 | EmbeddingGemma 2 1위 |
|---|---|---|
| a sunset over the sea | sunset_sea (0.29) | sunset_sea (0.70) |
| 빨간 동그라미 | red_circle (0.22, 2위와 차이 0.01) | red_circle (0.73) |
| night sky with the moon | night_sky_moon (0.30) | night_sky_moon (0.75) |

- CLIP은 한국어 쿼리에서 1·2위 점수 차이가 거의 없어 신뢰도가 낮고, EmbeddingGemma 2는 한국어 쿼리도 뚜렷하게 구분했습니다.
- 속도: CLIP은 이미지 5장 + 쿼리에 약 0.2초, EmbeddingGemma 2는 CPU에서 약 20초(이미지당 약 4초)입니다. 이미지가 많으면 GPU를 쓰세요.

## 이미지 · 영상 컬렉션

이미지와 영상은 **RAG 컬렉션의 문서**로 올립니다(컬렉션 → ① 문서, 글 문서와 섞어도 됨). 별도 저장소를 만들지 않은 이유는 청크 세트 → 벡터 인덱스 → 검색 비교 · 평가 세트 · 검색 향상 · 이력을 그대로 쓰고, 한 컬렉션에서 글과 그림을 함께 찾기 위해서입니다.

| 단계 | 이미지 | 영상 |
|---|---|---|
| 올리기 | 원본을 `data/media/doc-<id>/` 에 저장, 크기 확인(깨진 파일은 건너뜀) | `VIDEO_FRAME_INTERVAL`(기본 2초)마다 프레임을 뽑고, **직전 프레임과 거의 같은 장면은 버림**(16×16 흑백 축소본 평균 차 < 6). 최대 `VIDEO_MAX_FRAMES`(240)장, 프레임은 긴 변 768px JPEG |
| 청크 | 이미지 1장 = 청크 1개 (텍스트 청킹 설정과 무관) | 프레임 1장 = 청크 1개, 라벨에 시각(`드론 영상 0:04`) |
| 인덱스 | 멀티모달 모델이면 **그림으로** 인코딩, 텍스트 전용 모델이면 라벨(파일 이름)로만 색인하고 경고 | 같음 |
| 검색 | 결과에 썸네일, 누르면 원본 | 썸네일을 누르면 원본 영상을 그 장면 시각부터 재생(`#t=초`) |

- 같은 청크 세트에 이미지가 있으면 색인 · 검색 모두 모델을 **멀티모달 프로필**로 불러 텍스트와 그림이 같은 벡터 공간에 놓이게 합니다(청크 세트 통계 `n_media` 로 판단).
- 이미지에는 질의/문서 프롬프트를 붙이지 않습니다(텍스트용). 인덱스의 `truncate_dim`(MRL)은 그림에도 똑같이 적용됩니다.
- 영상 디코딩은 PyAV(FFmpeg 내장 휠)라 시스템에 ffmpeg 를 설치하지 않아도 됩니다. 같은 장면을 거르는 이유: 정지 화면이 길면 같은 그림이 검색 결과를 도배하고 인코딩 시간만 늘기 때문입니다.
- 멀티모달 화면 아래 **이미지 · 영상 컬렉션 검색**에서 결과를 썸네일 격자로 볼 수 있습니다.

### 실측 #2 · 2026-10-18 · 실제 사진 23장 + 슬라이드 영상 (run #224)

- 자료: Windows 기본 배경 사진 25장(같은 파일 2쌍은 중복으로 자동 제외 → 23장) + 사진 4장(호수 · 빛나는 원 · 리본 · 분홍 꽃)을 4초씩 이어 붙인 16초 영상. 파일 이름은 `img20.jpg` 처럼 뜻이 없어 **그림 내용으로만** 찾아야 합니다.
- 영상: 2초 간격 8장 중 같은 장면 4장을 버리고 장면이 바뀐 0 · 4 · 8 · 12초 4장만 남음 → 벡터 27개(사진 23 + 프레임 4).
- 평가 세트: 사진을 보고 쓴 질문 14개(한국어 10 · 영어 4), 정답 사진이 여럿인 질문 포함. 정답 문서 기준.

| 설정 | nDCG@10 (95% 구간) | Hit@1 | Hit@5 | 정답 문서 Recall@5 | 1위 대비 | 색인 시간 | 질의 지연 |
|---|---|---|---|---|---|---|---|
| EmbeddingGemma 2 (멀티모달) | **100.0** (100–100) | 100.0 | 100.0 | 95.2 | — | 122초 (그림당 약 4.5초) | 93ms |
| CLIP ViT-B/32 | 67.4 (42.9–88.8) | 64.3 | 71.4 | 52.4 | −32.6%p **유의** | 8초 | 26ms |
| BM25 (파일 이름) | 0.0 | 0.0 | 0.0 | 0.0 | 유의 | — | 1ms |

- EmbeddingGemma 2 는 한국어 · 영어 모두 14문항 전부 1위가 정답이었습니다. 정답이 하나뿐인 질문("해질녘 붉은 하늘 아래 호수", "초록색으로 빛나는 원", "투명한 구슬과 방울", "파란 꽃 모양 조형물", "단색 파란 화면")도 모두 맞혔습니다.
- CLIP 은 **영어 4문항은 모두 맞혔지만 정답이 하나뿐인 한국어 질문 5개는 모두 틀렸습니다**(텍스트 인코더가 영어 위주). 한국어 질문 중 맞힌 것은 정답 사진이 여러 장이라 우연히 맞기 쉬운 질문이었습니다. 한국어 서비스라면 다국어 멀티모달 모델이 필요하다는 근거입니다.
- BM25 0점은 파일 이름에 뜻이 없다는 대조군입니다 — 위 점수가 그림 내용에서 나왔다는 확인.
- 한계: 문항이 14개, 그림이 27개로 작고, 슬라이드 영상의 프레임은 같은 사진의 축소본이라 정답이 쉽게 겹칩니다. 실제 영상(움직임 · 자막 · 어두운 장면)과 비슷한 사진이 많은 자료로 다시 재야 합니다. CPU 색인은 그림당 약 4.5초라 수천 장이면 GPU 가 필요합니다.

## 오디오 / 비디오 임베딩

`sentence-transformers[audio,video]` extra는 이 환경(Python 3.14 + numpy 2.5)에서 의존성 해석이 실패해 기본 설치에서 뺐습니다(transformers[audio] → 구버전 numpy 요구). 필요하면 별도 환경에서 다음처럼 설치해 보세요.

```bash
uv pip install "sentence-transformers[audio,video]"
```

오디오는 16kHz 모노 입력을 권장합니다. 영상은 위처럼 프레임 이미지로 나눠 색인합니다(영상 자체를 하나의 벡터로 만드는 비디오 임베딩은 쓰지 않음 — 장면 단위로 찾고 그 시각으로 이동하기 위해). 오디오는 API 코드에서 `model.encode([{"audio": "file.wav"}])` 형태로 쓸 수 있습니다.
