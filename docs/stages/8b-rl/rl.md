# 강화학습 — 보상 · 방법 · 실측

'좋은 답'의 기준을 **보상 함수**로 정하고, 그 보상으로 답을 고르거나(Best-of-N) 선호 쌍을 모아 선호 학습(DPO) 데이터를 만듭니다. 화면은 `/rl`(강화학습 테스트)입니다.

## 보상 함수

| 항목 | 가중치 | 언제 |
|---|---|---|
| 근거 있는 문장 | +1 × 문장 근거율 | 답했을 때 |
| 정답 근거 인용 | +1 | 정답 근거 문장을 알 때(평가 세트) |
| 없는 근거 번호 인용 | −0.5 (최대 2개) | 답했을 때 |
| 근거가 있는데 거절 | −1 | 정답 근거를 알고, 그 근거가 검색됐을 때 |
| 정직한 거절 | +0.5 | 정답 근거를 알고, 검색되지 않았을 때 |
| 너무 김 (600자 초과) | −0.2 | 답했을 때 |

설명 가능한 단순 합으로 둔 이유: 학습된 보상 모델은 판단 근거를 알기 어렵고, 점수만 올리는 답(보상 해킹)을 찾기도 어렵습니다. 사람이 고른 선호와 보상이 얼마나 일치하는지(화면에서 사람이 고를 때 알려 줌)로 보상 함수를 고칩니다.

## 방법

- **Best-of-N (추론 시점 최적화)**: 평소 답(후보 0, 온도 0.1)과 다양한 후보(온도 0.9)를 만들어 보상 최고를 고릅니다. 학습 없이 보상의 효과를 바로 잴 수 있고 '학습하면 얼마나 좋아질 수 있나'의 대략적인 상한이 됩니다. 후보 0 이 평소 답이라 보상 기준으로는 나빠질 수 없고, 같은 실행 안에서 평소 답과 짝지어 비교합니다. 비용은 N 배. 연결 실행 · 라우팅의 답변 방식 '8b Best-of-4'로도 씁니다.
- **선호 쌍 모으기**: Best-of-N 평가에서 보상 차가 충분히 큰(기본 0.3) 최고 · 최저 답을 자동 저장하고, 화면에서 사람이 두 답 중 하나를 고를 수 있습니다. 근거(context)를 함께 저장합니다 — 선호는 '이 근거가 주어졌을 때' 어느 답이 나은가이기 때문입니다.
- **DPO 데이터 내보내기**: TRL 등이 읽는 대화형 선호 형식 JSONL (`prompt` · `chosen` · `rejected`). 이 PC(CPU · 내장 GPU)에서 LLM 가중치를 강화학습(PPO · GRPO) · DPO 로 직접 고치는 것은 현실적이지 않아 학습은 GPU 환경에서 합니다.
- DB: `preference_pairs` 테이블(마이그레이션 0006).
