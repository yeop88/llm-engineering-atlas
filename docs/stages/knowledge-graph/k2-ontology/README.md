# K2 · 온톨로지 설계 (Ontology design)

**상태: ⬜ 예정** — 도메인의 개념(클래스) · 속성 · 관계와 그 규칙을 기계가 읽는 스키마로 정의한다

## 원리

온톨로지는 지식 그래프의 설계도입니다. 어떤 클래스(개념)가 있고, 각 클래스가 어떤 속성(Property)과 관계(Relationship)를 갖는지, 관계의 방향 · 개수 · 값의 형식 같은 규칙을 정합니다. W3C 표준으로는 데이터 모델 RDF, 개념 · 관계 정의 OWL, 검증 규칙 SHACL 이 있고, 속성 그래프(Neo4j)에서는 노드 레이블 · 관계 타입 · 제약 조건으로 같은 일을 합니다.

## 왜 하는가

추출(K3)과 융합(K4)이 같은 설계도를 따라야 '판례가 조문을 인용한다'는 사실이 문서마다 다른 이름의 관계로 흩어지지 않습니다. 검증 규칙이 있어야 잘못 추출된 관계(조문이 판례를 인용 등)를 저장 전에 걸러 정합성을 지킬 수 있습니다.

## 어떻게 (이 앱에서)

- (예정) 원칙: 명확성(개념마다 정의 한 줄) · 정합성(검증 규칙) · 확장성(나중에 개념을 더해도 기존 관계가 깨지지 않게)
- (예정) 법률 예시 — 클래스: 법령 · 조문 · 항 · 판례 · 쟁점 · 당사자 유형 / 관계: 판례 -인용-> 조문, 조문 -속함-> 법령, 시행령 조문 -위임 근거-> 법률 조문, 판례 -다룸-> 쟁점
- (예정) 설계를 YAML(또는 OWL · SHACL)로 저장하고, 추출 프롬프트 · 그래프 DB 제약 조건 · Text2Cypher 스키마 설명을 모두 여기서 만든다
