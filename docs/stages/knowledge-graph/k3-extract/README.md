# K3 · 데이터 추출 (ETL & LLM extraction)

**상태: ⬜ 예정** — 정형 데이터는 스키마 매핑으로, 비정형 문서는 LLM 으로 [주어-관계-목적어] 트리플을 뽑는다

## 원리

정형 데이터(RDB · CSV)는 테이블 열을 온톨로지의 클래스 · 속성 · 관계에 대응시켜(매핑) 그대로 옮깁니다. 비정형 문서(보고서 · 판결문)는 LLM 으로 개체명 인식(NER)과 관계 추출(RE)을 해 [주어-관계-목적어] 트리플을 만듭니다. 추출 결과에는 근거 문장 · 문서를 함께 남깁니다.

## 왜 하는가

그래프의 품질은 추출에서 정해집니다. 정형 데이터가 있으면 추출보다 매핑이 정확하고 싸므로 먼저 쓰고, LLM 추출은 매핑으로 얻을 수 없는 관계에만 씁니다. 근거를 남겨야 GraphRAG 답변이 RAG 처럼 출처를 댈 수 있습니다.

## 어떻게 (이 앱에서)

- (예정) 정형: 판례 메타데이터의 참조조문 · 사건번호 · 선고일 → 판례 · 조문 노드와 '인용' 관계 (추출 없이 바로 — 이미 수집한 자료)
- (예정) 비정형: 판결요지 · 조문 본문에서 LLM(로컬 Gemma 4) 으로 쟁점 · 요건 · 효과 관계 추출, 온톨로지(K2)에 없는 관계 타입은 버림
- (예정) 추출 정확도를 사람 판정 표본으로 측정(트리플 정밀도 · 재현율) — 답변 검증 보정과 같은 방식

- LLM 트리플 추출 + 검증 규칙 + 사람 판정 표본
