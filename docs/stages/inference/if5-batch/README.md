# IF5 · 연속 배칭 (Continuous batching)

**상태: ⬜ 예정** — 슬롯 수 · 배칭 방식으로 처리량과 꼬리 지연을 맞춘다

## 원리

연속 배칭은 걸음마다 끝난 요청을 빼고 새 요청을 넣어 장치를 쉬지 않게 하는 스케줄링입니다. 슬롯 수를 늘리면 처리량이 늘지만 요청 하나의 생성은 느려집니다.

## 왜 하는가

처리량만 보고 슬롯을 늘리면 p95 지연이 무너집니다. 둘을 함께 봐야 합니다.

## 어떻게 (이 앱에서)

- (기반) 연속 배칭(BM5)
- (예정) 슬롯 수별 처리량 · p95 · 성공 작업당 비용
