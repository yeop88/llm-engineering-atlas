# IF1 · 워크로드 측정 (Workload profiling)

**상태: ⬜ 예정** — 실제 요청의 프롬프트 · 답 길이 · 동시 수 · 지연 분포를 잰다

## 원리

워크로드 측정은 운영 요청 기록에서 프롬프트 · 답 토큰 분포, 동시 요청 수, 단계별 지연(검색 · 미리 채우기 · 생성)을 재 최적화의 기준선을 만드는 것입니다.

## 왜 하는가

워크로드를 모르고 고른 최적화는 다른 워크로드에 맞춘 것일 수 있습니다. 같은 기법도 프롬프트가 긴지 답이 긴지에 따라 효과가 반대입니다.

## 어떻게 (이 앱에서)

- (기반) 비용 · 지연(E4) · 트레이싱(E3)
- (예정) 요청 기록에서 길이 · 동시 · 단계 지연 분포 기준선

## 화면

- 아직 테스트 화면이 없습니다. 단계 소개는 앱의 `/stages/if_measure` 에서 볼 수 있습니다.
