# IF2 · 미리 채우기 · 생성 분리 (Prefill / decode split)

**상태: ⬜ 예정** — 미리 채우기(연산 한계)와 생성(대역폭 한계)을 따로 재고 따로 다룬다

## 원리

미리 채우기는 프롬프트를 한꺼번에 읽어 연산이 한계이고, 생성은 토큰마다 가중치를 다시 읽어 메모리 대역폭이 한계입니다. 둘을 나눠 재고, 큰 서비스는 서로 다른 장비에 나눠 돌립니다.

## 왜 하는가

두 단계의 병목이 달라 같은 최적화가 한쪽만 빨라지게 합니다. 이 PC 실측에서 근거 읽기(미리 채우기)가 지연의 2/3 였습니다.

## 어떻게 (이 앱에서)

- (기반) 추론 서버 실측(S4) · 지붕선 어림(BM1)
- (예정) 미리 채우기 · 생성 토큰/초 분리 · 병목 표시

## 화면

- 아직 테스트 화면이 없습니다. 단계 소개는 앱의 `/stages/if_split` 에서 볼 수 있습니다.
