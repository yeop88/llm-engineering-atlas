# 장기 실행 업무 — 계획 · 체크포인트 · 승인 · 복구 · 완료 판정 · 실측 (LR1~LR7)

화면은 `/longrun/runs`(업무 계획 · 실행) · `/longrun/approvals`(승인 · 완료 판정), 코드는 `app/stages/longrun/` 입니다.

```
목표 ─ 계획(템플릿 · LLM) ─ 계획 검사(등록된 행동만 · 의존 · 발송 앞 승인) ─ 업무(lr_runs) · 단계(lr_steps)
   └ 실행기: 다음 단계 → 범위 검사 → 실행(재시도) → 체크포인트 저장 ─┬─ 승인 단계: 멈춤 → 사람 승인 → 이어 하기
                                                                 ├─ 실패: 대체 행동 → 남은 단계 재계획(2번까지)
                                                                 └─ 끝: 완료 조건 판정 → 완료 / 검토 필요
   되돌리기: 끝난 단계의 보상 작업을 나중 것부터(발송 → 파일 삭제 · 철회 알림)
```

## 설계

- **계획은 등록된 행동만.** 행동 10개(AS 문의 모으기 · 질문 모으기 · 집계 · 자료 찾기 · 질문 일괄 답변 · 보고서 초안(LLM) · 보고서 초안(집계만) · 완료 조건 검사 · 사람 승인 · 보고서 발송)만 계획에 쓸 수 있습니다(`app/stages/longrun/actions.py`). 아무 행동이나 실행하게 두면 계획 오류가 곧 사고가 됩니다. LLM 계획은 JSON 으로 받아 계획 검사(`plans.validate`)를 거칩니다 — 모르는 행동은 거절, 의존은 앞 단계만, 되돌릴 수 없는 행동 앞에 승인 단계가 없으면 끼웁니다(맵 원칙: 되돌릴 수 없는 행동은 승인 후에).
- **'갈 수 있는 데까지' 실행.** 실행기(`runner.advance`)는 의존이 끝난 다음 단계를 하나씩 돌리고, 승인 대기 · 상한 · 반려에서 상태만 남기고 끝납니다. 승인 · 범위 늘리기 · 이어 하기가 다시 실행기를 부릅니다 — 며칠짜리 업무를 스레드 하나가 붙잡고 기다리지 않게.
- **단계마다 체크포인트.** 단계가 끝날 때마다 결과를 DB 에 저장합니다(`lr_steps.output`, 마이그레이션 0015). 백그라운드 작업은 메모리에서 돌아 서버가 다시 뜨면 사라지지만, 업무는 시작할 때 돌던 업무를 '중단됨', 돌던 단계를 '다시 할 단계'로 돌려 이어 하기가 마지막 체크포인트 다음부터 합니다(맵 원칙: 중단은 정상이다).
- **복구 순서.** 같은 행동을 한 번 더(LLM 서버 끊김 같은 일시적 오류) → 대체 행동(LLM 초안 → 집계만으로 만든 보고서, LLM 이 멈춰도 업무가 숫자 보고서로는 끝나게) → LLM 으로 남은 단계 재계획(업무당 2번). 되돌릴 수 없는 행동은 재계획하지 않습니다 — 실패 원인을 모른 채 다른 방법으로 다시 보내면 두 번 보낼 수 있습니다.
- **멱등과 보상.** 단계마다 멱등 키가 있어 발송 단계가 재시도 · 이어 하기로 다시 와도 같은 파일 이름 · 같은 `Idempotency-Key` 로 두 번 보내지 않습니다. 행동마다 보상 작업을 두고(발송 → 파일 삭제 · 웹훅 철회 알림), '되돌리기'는 끝난 단계를 나중 것부터 보상합니다. 집계 · 초안처럼 부작용이 없는 단계는 보상할 것이 없습니다.
- **완료는 검사로.** '다 했다'는 에이전트의 말이 아니라 완료 조건으로 정합니다(`verify.check`): 필수 절, 보고서의 숫자가 모두 집계 · 인용한 자료에 있나(지어낸 숫자), 인용 번호가 자료 범위 안인가, 자료와의 근거 일치 0.6 이상, 승인 · 발송을 했나. 하나라도 미달이면 '완료'가 아니라 '검토 필요'로 끝납니다. 승인 화면에도 같은 검사를 보여, 무엇을 승인하는지 알고 승인하게 합니다.
- **범위.** 업무마다 허용 행동 · 컬렉션 · 단계 수 · 시간 · 비용(토큰 단가)을 정하고, 넘으면 멈춥니다. 늘리는 것은 관리자만 — 상한은 잘못된 계획 · 반복을 사람이 보게 하는 장치입니다. 검색 · 답변 행동은 문서 권한(G3)을 그대로 씁니다.
- **개인정보.** AS 문의 모으기는 의도 · 제품 · 오류 코드 · 상태만 담고 고객 키 · 대화 원문은 담지 않습니다 — 보고서에 필요한 건 분포입니다.
