# PF6 · 장애 대응 · 대체 모델 (Resilience & fallback)

**상태: ✅ 구현됨** — 모델 서버 · 벡터 DB · 외부 API 가 멈추면 대체 경로로 넘어가고, 품질 차이를 알린다

## 원리

대체(fallback) 경로는 큰 모델 → 작은 모델, 로컬 → 클라우드 API, 벡터 검색 → 키워드 검색 처럼 미리 정해 둡니다. 재시도 · 시간 제한 · 차단기(실패가 계속되면 잠시 안 부름)를 함께 씁니다.

## 왜 하는가

단일 모델 서버는 단일 장애점입니다. 대체 경로의 품질을 미리 재 두지 않으면 장애 때 무엇을 잃는지 모릅니다(E2B 는 품질 −13).

## 어떻게 (이 앱에서)

- LLM 차단기(같은 대상 5번 연속 실패 → 30초 동안 건너뜀 → 한 번 시험)와 대체 사슬(LLM_FALLBACKS), 대체로 답하면 요청 기록 guard.fallback
- 벡터 DB 가 멈추면 같은 청크 세트의 BM25 로(연결 계층), 결과 · 요청 기록에 degraded 표시
- 대체 사슬 점검(모델마다 짧게 불러 살아 있는지)
