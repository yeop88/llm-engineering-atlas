# 엔터프라이즈 AI 플랫폼 — 게이트웨이 · 테넌트 · 프롬프트 · 플래그 · 장애 대응 · 비용 · 실측 (PF1~PF7)

화면은 `/platform/gateway`(게이트웨이 · 테넌트) · `/platform/registry`(프롬프트 · 기능 플래그) · `/platform/ops`(배포 · 장애 대응 · 비용), 코드는 `app/stages/platform/` 이고, 서비스 경로에는 연결 계층(`app/pipeline/search.py` · `serve.py`)에 끼워져 있습니다.

```
요청 ─ 인증(토큰 · 그룹) ─ 속도 제한(사용자 · 테넌트, 분당) ─ 화면 · API
 서비스 답변: 플래그(방어 모드 · 고지 · 관련성) → 검색(테넌트 격리 → 문서 권한 → 벡터 DB 멈추면 BM25)
            → 프롬프트(레지스트리 활성 버전) → LLM(차단기 · 대체 사슬) → 요청 기록(버전 · 대체 · 비용) → 비용 배분 · 예산
```

## 설계

- **속도 제한은 인증 안쪽에서.** 미들웨어는 나중에 등록한 것이 바깥이라, 속도 제한을 인증보다 먼저 등록해 인증이 사용자를 정한 뒤 셉니다. 사용자 · 테넌트 단위(분당, 이동 창 60초) — 한 고객사가 몰아서 부르면 다른 고객사가 느려지는 것을 막으려고. 사용량은 메모리에서 경로 묶음별로 세고(요청마다 DB 에 쓰면 그 자체가 부하), 서비스의 토큰 · 비용은 요청 기록에 따로 남습니다. 서버가 여럿이면 각자 세는 한계가 있습니다.
- **테넌트 격리는 검색 전에.** 테넌트는 사용자 그룹 `tenant:<이름>`, 컬렉션을 테넌트에 묶으면 다른 테넌트 사용자의 검색에서 그 컬렉션이 통째로 빠집니다(`pipeline.search.restrict`). 문서 권한(G3)과 같은 자리 — 답변 뒤에 지우면 LLM 이 이미 읽었습니다. 전체 권한(`*`, 관리자 · 로컬)은 모두 보고, 묶지 않은 컬렉션은 공용입니다. 누출 시험은 테넌트마다 남의 컬렉션을 그 테넌트 그룹으로 서비스와 같은 연결 계층으로 검색합니다.
- **프롬프트 버전.** 답변 규칙 하나를 바꿔도 같은 질문의 답이 바뀝니다. 시스템 프롬프트를 버전으로 쌓고(`pf_prompts`, 마이그레이션 0017) 하나만 활성으로 두면, 요청 기록에 `signals.prompt = answer_system@버전`이 남아 품질이 떨어진 시점의 버전을 찾을 수 있고, 이전 버전을 다시 활성으로 하면 바로 되돌아갑니다. 활성 버전이 없으면 코드 기본값입니다.
- **기능 플래그.** 기본값 + 대상 규칙(테넌트 · 그룹 · 사용자 · 비율, 첫 번째로 맞는 것). 비율은 사용자 이름 해시라 같은 사용자는 늘 같은 값입니다. 서비스 답변이 `guard_mode` · `ai_notice` · `answer_relevance` 를 읽고(요청이 직접 고른 값 → 플래그 → 설정), 요청마다 DB 를 읽지 않게 10초 기억합니다. 바꾼 기록(누가 · 전후)을 50개까지 남깁니다.
- **차단기와 대체 모델.** 같은 LLM 이 5번 연달아 실패하면 30초 동안 부르지 않고 바로 대체 사슬(`LLM_FALLBACKS`)로 — 죽은 서버를 매번 기다리면(시간 초과 120초) 모든 요청이 느려집니다. 30초 뒤 한 번 시험해 성공하면 다시 엽니다. 대체로 답하면 `guard.fallback` 이 요청 기록에 남습니다 — 같은 품질이 아니라는 것을 숨기지 않습니다. 스트리밍 답변은 아직 대체하지 않습니다.
- **벡터 DB 대체.** 벡터 DB 가 멈추면 같은 청크 세트의 BM25 로 찾고 결과에 `degraded` 를 붙입니다(검색이 통째로 실패하는 것보다 낱말 검색이라도). 연달아 실패하면 같은 차단기가 열려 벡터 DB 를 기다리지 않습니다.
- **비용은 요청 기록에서.** 요청 기록이 그룹 · 종류(기능) · 토큰 · 비용을 이미 남기므로 따로 세지 않습니다 — 두 곳에서 세면 숫자가 어긋납니다. 로컬 LLM 은 단가가 0 이라 비용은 0 이고 토큰으로 봅니다. 테넌트 월 예산에 경보 비율로 닿으면 한 달에 한 번 알립니다.
