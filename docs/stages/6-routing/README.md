# 6 · 라우팅 (Model routing)

**상태: ✅ 구현됨** — 질문의 난이도를 먼저 판단해 쉬운 질문은 싼 경로, 어려운 질문은 비싼 경로로 보낸다

## 원리

질문을 먼저 분류해, 쉬운 질문은 작고 빠른 모델 · 짧은 경로로, 어려운 질문은 크고 정확한 모델(에이전트) · 전체 경로로 보냅니다. 판단 방법은 규칙(질문 형태), 검색 확신도(1·2위 점수 차), LLM 판단을 비교합니다.

## 왜 하는가

모든 질문을 가장 비싼 경로로 처리하면 느리고 비쌉니다. 연결 실측에서 지연의 대부분이 답변 LLM 과 CPU 리랭커였으므로, 리랭커 · 큰 모델이 필요 없는 질문을 가려내면 품질을 지키며 비용을 줄일 수 있습니다.

## 어떻게 (이 앱에서)

- 쉬운 경로(1 → 2 → 답변)와 전체 경로(4 → 1 → 2 → 3 → 답변)를 정하고 라우터가 질문마다 고름 — 경로마다 답변 모델 지정 가능(7 소형 모델 자리)
- 평가: 질문마다 두 경로를 한 번씩 실행해 두고 라우터별 결과를 그 기록으로 계산 — 항상 쉬움 · 항상 전체 · 오라클(상한)과 비교, 확신도 기준값 곡선
- 연결 실행(맵)에서도 라우팅을 켤 수 있음 — 확신도 라우터는 먼저 한 검색을 쉬운 경로에서 재사용

## 화면

- `/routing` — **라우팅 테스트**: 라우터 판단 · 평가 세트 비용-품질 비교

## 앞으로 할 일

- 7 소형 모델이 생기면 쉬운 경로의 답변 모델 교체
- 임베딩 분류기 라우터(의미 응용의 분류기 재사용, 라벨 = 오라클 판단)
- 질문 수를 늘려 재측정
