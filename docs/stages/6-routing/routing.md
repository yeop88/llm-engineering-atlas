# 라우팅 — 라우터 · 평가 방법 · 실측

질문의 난이도를 먼저 판단해, 쉬운 질문은 **빠른 경로**로, 어려운 질문은 **전체 경로**로 보냅니다. 목표는 "항상 전체 경로"의 품질을 지키면서 비용(지연)을 줄이는 것입니다. 화면은 `/routing`(라우팅 테스트)이고, 맵의 **연결 실행**에서도 라우팅을 켤 수 있습니다.

## 지금의 두 경로

맵에서 라우팅은 답변 모델을 고르는 단계입니다(쉬운 질문 → 7 증류 · 양자화된 소형 모델, 어려운 질문 → 8 에이전트 LLM). 7 · 8 이 아직 없어서, 지금은 두 경로가 같은 LLM 을 쓰고 **검색 단계가 다릅니다**.

| 경로 | 단계 | 비용 |
|---|---|---|
| 빠른 경로 | 1 질의 임베딩 → 2 검색 → 답변 | 검색 0.2초 + 답변 |
| 전체 경로 | 4 검색 향상 → 1 → 2 → 3 리랭킹 → 답변 | + 향상(다중 질의 약 6초) + CPU 리랭커(약 22초) |

경로마다 답변 모델(`model`)을 지정할 수 있게 해 두었습니다. 7 소형 모델이 생기면 빠른 경로에만 지정하면 맵의 원래 모양이 됩니다.

## 라우터

| 라우터 | 판단 | 추가 비용 | 성격 |
|---|---|---|---|
| 규칙 | 이유 · 방법 · 비교 · 조건을 묻는 말(왜 · 어떻게 · 절차 · 차이 · 불이익 …), 45자 초과, 여러 가지를 함께 물음 → 어려움 | 0 | 설명 가능, 문서와 무관 |
| 검색 확신도 | 빠른 경로로 먼저 검색해 (1위 − 2위) / 1위 점수가 기준보다 작으면 → 어려움 | 어려움일 때 먼저 한 검색(0.2초)이 버려짐 | '이 문서 모음에서' 어려운지 봄 |
| LLM 판단 | LLM 에게 easy / hard 를 물음(형식이 어긋나면 어려움) | 질문마다 LLM 호출 수 초 | 가장 유연 |

- 확신도에 1위 점수가 아니라 **1 · 2위 차이**를 쓰는 이유: 점수 수준은 모델 · 질문 길이마다 달라 기준을 잡기 어렵지만, '다른 후보보다 얼마나 뚜렷한가'는 비교적 안정적입니다.
- 확신도 라우터가 쉬움으로 판단하면 먼저 한 검색을 그대로 이어 씁니다(같은 검색을 두 번 하지 않음).
- 판단을 못 하면(결과 1개 이하 · LLM 응답 해석 실패) **어려움**으로 보냅니다. 잘못 쉬움으로 보내 품질을 잃는 쪽이 비용을 조금 더 쓰는 쪽보다 나쁘기 때문입니다.

### 학습 라우터

평가 기록에는 질문마다 '어느 경로가 실제로 나았나'(오라클)가 이미 있습니다. 그것을 라벨로 분류기를 학습합니다 — 추가 실험 비용 없이 여러 신호를 함께 씁니다.

- 입력: 질문 임베딩(주제 · 형태) + 검색 확신도 + 규칙 신호(길이 · 이유/방법을 묻는 말 수 · 여러 요구 · 물음표 수)
- 라벨: 전체 경로 품질 > 빠른 경로 품질 + margin 이면 어려움(동점은 쉬움 — 오라클과 같은 규칙)
- 모델: 로지스틱 회귀(`class_weight=balanced`). 질문이 수십~수백 개라 큰 모델은 외워 버립니다.
- 채점: **교차검증 예측**(그 질문을 빼고 학습한 모델로 판단)으로 같은 기록의 다른 라우터와 나란히 비교. 같은 질문으로 배우고 채점하면 오라클에 가깝게 부풀려집니다. 어려움 확률 기준 0.3~0.7 을 훑은 표도 함께 냅니다.
- 쓰기: 저장하면 맵(연결 실행)의 라우팅 선택지에 '학습 라우터 #id' 로 나옵니다. 확신도 신호를 쓰므로 확신도 라우터처럼 빠른 경로로 먼저 검색하고, 쉬움이면 그 검색을 이어 씁니다.
- 한계: 쉬움 · 어려움이 각각 2개 이상 있어야 학습합니다. 질문이 적으면 결과가 크게 흔들리므로 질문 수를 늘려 재측정하세요. 평가 기록의 문서 모음 · 경로 설정에 맞춘 라우터라, 설정이 바뀌면 다시 학습합니다.

## 평가 방법

- 질문마다 **두 경로를 한 번씩** 실행해 두고, 라우터의 결과는 '고른 경로의 기록'으로 계산합니다. 라우터마다 다시 실행하면 LLM 답변 · 리랭킹을 라우터 수만큼 반복해야 하고, 같은 기록을 쓰므로 라우터 사이 차이에 LLM 답변의 무작위성이 섞이지 않습니다.
- 품질: 답변을 켜면 **정답 근거를 인용했는가**(근거 문장이 없으면 문장 근거율), 끄면 nDCG@10.
- 지연: 고른 경로의 처리 시간 + 라우터 비용(LLM 판단 호출, 확신도가 어려움일 때 버린 첫 검색).
- 비교 대상: 항상 빠른 경로(가장 쌈) · 항상 전체 경로(품질 목표) · **오라클**(질문마다 실제로 나았던 경로 = 라우팅으로 얻을 수 있는 상한, 동점이면 싼 쪽). '전체 경로 대비 품질'은 항상 전체 경로와의 짝지은 차이와 95% 구간입니다.
- 확신도 기준값을 관측값 사이로 훑어 **비용-품질 곡선**을 그립니다(어려움 비율 0% → 100%).

## 실측

### #2 · 2026-10-19 · 법률 공개 자료 · 40문항 (run #242, 학습 라우터 #9)

- 빠른 경로: KURE 의미 검색 → 답변. 전체 경로: 하이브리드 → 리랭커 상위 10 + **융합** → 답변. 답변 모두 Gemma 4 E4B, 프롬프트 캐시 끔. 품질 = 정답 근거 인용(답 없는 질문은 올바른 거절). 평가 세트 #5 에서 시드 3 으로 40문항.
- 전체 경로를 처음엔 리랭커 단독(융합 없음)으로 시작했다가 멈췄습니다 — 같은 자료의 리랭커 평가(run #241)에서 단독은 −2.3 이라 '비싼 경로가 더 나쁜' 비교가 되기 때문입니다.

| 라우터 | 전체 경로로 보냄 | 품질 [95% 구간] | 질문당 지연 평균 / p95 |
|---|---|---|---|
| 항상 빠른 경로 | 0% | 55.0 [37.5, 70.0] | 40.1 / 61.0초 |
| 항상 전체 경로 | 100% | 65.0 [50.0, 80.0] | 73.0 / 105.4초 |
| 규칙 (질문 형태) | 92.5% | 62.5 | 70.8초 |
| 검색 확신도 (0.05) | 85.0% | 65.0 | 68.4초 |
| LLM 판단 | 95.0% | 62.5 | 77.3초 |
| **학습 라우터** (어려움 확률 ≥ 0.4, 교차검증) | 37.5% | **65.0** | **55.1초** |
| 학습 라우터 (≥ 0.5, 교차검증) | 17.5% | 57.5 | 47.6초 |
| 오라클 (상한) | 12.5% | 67.5 | 45.5초 |

읽은 것

- 전체 경로가 빠른 경로보다 +10점(불확실, 40문항). 질문별로는 전체 경로가 나은 질문 5 · 빠른 경로가 나은 질문 1 · 같음 34 — 오라클은 **8문항 중 1문항만** 비싼 경로로 보내도 됐습니다.
- 사람이 정한 라우터는 법률 질문에 맞지 않았습니다. 규칙은 45자 기준이 공공문서의 짧은 질문에 맞춘 값이라 판결 상황 질문(중앙값 82~144자)을 거의 다 '어려움'으로, LLM 판단도 95% 를 어려움으로 보냈습니다. 확신도도 85% — 비슷한 판례가 많아 1 · 2위 점수 차가 작습니다. **셋 다 절약이 거의 없습니다**(지연 −3~−6%).
- **학습 라우터**(같은 기록으로 학습 · 5겹 교차검증)는 기준 0.4 에서 항상 전체 경로와 **같은 품질로 지연 −25%**(73.0 → 55.1초)였습니다. 이번 측정에서 가장 나은 실제 라우터입니다. 다만 '어려움' 라벨이 **5개뿐**이라 결과가 크게 흔들립니다(기준 0.5 에선 품질 57.5) — 질문을 늘려 다시 학습 · 측정해야 결론입니다. 저장된 라우터 #9 는 맵의 라우팅에서 고를 수 있습니다.
- 규칙 라우터의 글자 수 기준은 자료마다 다릅니다 — 법률 자료에 쓰려면 기준을 질문 길이 분포에 맞추거나 학습 라우터를 쓰세요.

### #1 · 2026-10-18 · 공공문서 · 직접 작성 24문항 (run #228)

- 빠른 경로: KURE-v1 의미 검색 → 근거 5개 → Gemma 4 E4B 답변. 전체 경로: 다중 질의 3개 → 의미 검색 → Qwen3-Reranker-0.6B(CPU, 상위 10) → 같은 LLM 답변.
- 품질 = 정답 근거 인용(질문마다 0 또는 1). 라우터 기준: 확신도 0.05, 규칙 45자.

| 라우터 | 어려움 비율 | 품질 | 전체 경로 대비 | nDCG@10 | 지연 평균 | 지연 절감 |
|---|---|---|---|---|---|---|
| 항상 빠른 경로 | 0% | 95.8 | ±0 [−12.5, +12.5] | 89.9 | 28.0초 | 47% |
| 항상 전체 경로 | 100% | 95.8 | — | 84.3 | 52.8초 | — |
| 규칙 | 25% | **100** | +4.2 [0, +12.5] 불확실 | 91.6 | 34.8초 | **34%** |
| 검색 확신도 (기준 0.05) | 67% | 100 | +4.2 불확실 | 89.4 | 46.1초 | 13% |
| LLM 판단 | 67% | 100 | +4.2 불확실 | 81.9 | 49.5초 | 6% |
| 오라클 (상한) | 4% | 100 | +4.2 불확실 | 89.1 | 28.5초 | 46% |

읽은 것

- **두 경로의 품질이 같았습니다(둘 다 95.8%).** 결과가 갈린 질문은 24개 중 2개뿐 — "보고서에 영어 약어를 … 어떻게 써야 하죠?"는 전체 경로만, "구매대행 업자 등록 신청서는 어느 세관에 …"는 빠른 경로만 맞혔습니다. 그래서 오라클은 1개만 전체 경로로 보내고도(4%) 100% 를 냅니다 — 이 자료에서는 **대부분의 질문에 비싼 경로가 필요 없었다**는 뜻입니다.
- 규칙 라우터는 그 두 질문을 모두 맞는 쪽으로 보내 100% 를 냈고, 지연은 항상 전체 경로보다 34% 짧았습니다. 다만 차이가 1문항이라 '불확실'입니다 — 규칙이 우월하다는 근거가 아니라, **품질을 잃지 않고 비용을 줄였다**는 정도로 읽어야 합니다.
- 검색 확신도는 KURE 의 1 · 2위 점수 차가 대부분 0.05 미만(중앙값 약 0.03)이라 기준 0.05 에서 3분의 2 를 어려움으로 보냈습니다. 기준값 곡선을 보면 0.012 이상에서 이미 100% 였고(어려움 21%, 34.4초) — **기준값은 모델마다 곡선을 보고 정해야** 합니다. 이 결과를 보고 고르면 과적합이므로 다른 질문으로 확인이 필요합니다.
- LLM 판단은 판단 호출(평균 수 초)이 붙고 어려움 비율도 높아 가장 덜 절약했습니다. 질문 형태가 길고 구어체이면 대부분 '어렵다'고 봤습니다.
- 측정 주의: 이 실측 무렵에는 비교 측정에서 llama-server 의 프롬프트 캐시를 끄지 않았습니다. 앞선 연결 비교(#227)와 겹치는 질문 · 근거가 있어 일부 지연이 짧게 잡혔을 수 있습니다(품질에는 영향 없음). 지금은 연결 비교 · 라우팅 평가가 캐시를 끄고 잽니다.
- 한계: 품질 차이가 나는 질문이 2개뿐이라 라우터끼리의 우열은 가릴 수 없습니다. 두 경로의 품질 차이가 큰 자료(긴 상황 설명형 · 여러 문서를 엮어야 하는 질문)와 7 소형 모델이 들어간 빠른 경로로 다시 재야 라우팅의 효과가 분명해집니다.
