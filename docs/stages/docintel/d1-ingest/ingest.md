# 수집 · 메타데이터 · 증분 갱신 (D1 · D6)

화면은 `/docintel/sources`(폴더 소스 · 청크 세트 상태 · 문서 메타데이터)입니다.

## D1 폴더 수집

- 소스 = 컬렉션 + 폴더 + 파일 패턴(`*.pdf`) + 주기(분, 0 이면 손으로만).
- **허용 경로 안만**: 기본은 `data/inbox`, 더 열려면 `INGEST_ROOTS`. 화면에서 서버의 아무 폴더나 읽게 두면 웹 화면이 서버 파일 읽기 창구가 됩니다. 소스 추가 · 삭제는 관리자만(`API_USERS` 를 쓸 때).
- 동기화는 파일 sha 로 판단합니다: 새 파일 → 올림, 내용이 바뀐 파일 → 옛 문서를 지우고 새로 올림, 사라진 파일 → 문서 삭제, 같은 파일 → 그대로. 파일 이름 · 수정 시각이 아니라 내용으로 보므로 복사 · 이동만 한 파일은 다시 처리하지 않습니다.
- 사라진 파일의 문서를 **새 파일을 올리기 전에** 지웁니다. 순서가 반대면 '이름만 바뀐 같은 내용' 파일이 중복으로 건너뛰어진 뒤 옛 문서가 지워져 내용이 사라졌습니다(구현 중 발견해 고침).
- 주기 수집은 앱 안 1분 주기 스레드(`app/main.py` 의 `_periodic`)가 띄웁니다. 별도 스케줄러를 두지 않은 이유: 할 일이 둘뿐이고(수집 · 기록 정리), 앱이 꺼지면 같이 멈춰야 합니다. 같은 소스가 이미 돌고 있으면 건너뜁니다.
- 올린 파일의 **원본을 sha 별로 보관**합니다(`data/uploads/`). OCR · 표 추출처럼 처리 방법이 바뀌면 원본에서 다시 뽑아야 하는데, 0010 이전에 올린 문서는 원본이 없어 다시 올려야 합니다.

## D6 메타데이터 · 증분 갱신

- 문서 메타: 종류 · 부서 · 제품 모델 · 날짜 · 권한(acl) · 옛 판(superseded). 화면에서 바로 고치고, 컬렉션의 값 모음(facets)을 칩으로 보여 줍니다.
- 검색 설정 `filters`(종류 · 부서 · 제품 모델 · 날짜 범위 · 최신판만)는 연결 계층이 허용 문서로 바꿔 권한(G3)과 겹칩니다. 메타를 바꿔도 청크는 그대로라(검색 때 문서 단위로 거름) 다시 색인할 필요가 없습니다.
- **증분 갱신**: 글을 바꾸는 모든 처리(OCR · 표 추출 · 정제 · 개인정보 가리기 · 폴더 동기화)가 문서에 바뀐 시각(`changed_at`)을 남깁니다. 청크 세트의 마지막 갱신 시각보다 뒤에 바뀐 문서만 옛 청크 · 벡터를 지우고 다시 청크 · 임베딩합니다(그 청크 세트의 모든 인덱스).
