# 데이터 계보 · 근거 — 요청 → 청크 → 문서 · 판 사슬 · 주장 나누기 · 표시 일치 · 부딪힘 · 주장 단위 평가 · 실측 (PV1~PV8)

화면은 `/provenance/trace`(근거 계보) · `/provenance/check`(근거 검증 · 부딪힘), 코드는 `app/stages/provenance/` 입니다. 새 기록을 만들지 않고 이미 있는 요청 기록(해시 사슬) · 청크 · 문서 메타를 이어 보여 줍니다 — 따로 저장하면 기록과 어긋날 수 있어서.

```
답 → 문장 → 주장(쉼표 · 접속 표현) → 인용 [n] · 가장 겹치는 근거 · 표시(숫자 · 조문 · 코드) 일치 → 강함 · 약함 · 없음 · 인용 안 함 (PV5 · PV7)
요청 기록 → 근거 청크(쪽 · 글자 범위 · 조문) → 청크 세트(나눈 방식) → 문서(sha256 · 수집 시각 · 파서 · 라이선스) → 같은 원본의 판들 (PV1~PV4 · PV6)
같은 질문의 다른 답 → 표시 집합이 다르면 부딪힘 (PV8)
평가 세트 → 서비스 답변 → 주장 단위 지표 (PV8)
```

## 설계

- **주장 단위로 나눈다(PV5).** 근거 일치 검증(2)의 '근거 있는 문장 비율'은 한 문장 안의 맞는 주장과 틀린 주장을 가르지 못합니다. 답을 문장으로, 문장을 쉼표 · '그리고 · 또한 · 하지만 · 다만' 으로 나눠 6글자 이상인 조각을 주장으로 봅니다. 인용 번호는 문장 단위로 붙어 있어 그 문장의 주장들이 함께 씁니다.
- **표시가 근거에 있어야 강함(PV5 · PV7).** 주장마다 글자 3-gram 이 가장 많이 겹치는 근거와 겹침 비율을 재고, 주장의 숫자 · 조문 번호 · 코드(단위 포함)가 인용한 근거(인용이 없으면 가장 겹치는 근거)에 그대로 있는지 봅니다. 겹침 0.2 미만은 근거 없음, 표시가 빠졌으면 겹침과 상관없이 근거 약함(숫자 하나가 틀린 답이 가장 위험), 겹침 0.45 이상이면 강함입니다. 인용이 없으면 '인용 안 함'. 인용한 근거가 가장 겹치는 근거와 다르면 '인용과 다름' 으로 표시합니다.
- **원본까지 잇는다(PV1~PV4 · PV6).** 요청 기록의 근거 청크 번호에서 청크(문서 안 순번 · 쪽 · 글자 범위 · 조문 메타) → 청크 세트(나눈 전략 · 만든 시각) → 문서(파일 이름 · sha256 · 수집 시각 · 출처 · 라이선스 · 파서 기록) → 컬렉션으로 갑니다. 판은 같은 컬렉션에서 같은 원본(출처 키 · URL · 법령 id · 파일 이름 순으로 찾음)인 문서를 받은 순서로 늘어놓아 정하고, 지금 판이 아닌 문서를 근거로 답했으면 '옛 판 근거' 입니다 — 옛 판에서 나온 답은 그때는 맞았어도 지금 틀릴 수 있습니다.
- **추적 가능한 비율(PV7).** '근거 강함이면서 인용이 유효한 주장' 의 비율을 원본까지 추적 가능한 비율로 셉니다. 인용 정확도는 인용한 근거가 가장 겹치는 근거와 같은 주장의 비율입니다.
- **부딪힘은 같은 질문끼리(PV8).** 요청 기록에서 질문이 거의 같은(글자 3-gram 자카드 0.8 이상) 두 답의 표시 집합이 다르면 부딪힘 후보로 보여 줍니다(어느 쪽이 맞는지는 사람이). 평가는 평가 세트 질문을 서비스 답변으로 답하게 해 주장 단위 지표 · 옛 판 근거 수 · 정답 근거 인용을 함께 냅니다.
