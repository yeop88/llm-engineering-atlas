# DA6 · 권한 · 안전 (Access control & query safety)

**상태: ✅ 구현됨** — 읽기 전용 · 행 · 열 권한 · 개인정보 열 · 무거운 질의를 막는다

## 원리

분석 에이전트는 DB 에 직접 닿으므로 읽기 전용 계정 · 행 · 열 권한 · 개인정보 열 가리기 · 시간 · 행 수 상한을 DB 쪽에서 겁니다.

## 왜 하는가

프롬프트로 'DELETE 하지 말라'고 하는 것은 방어가 아닙니다. 권한은 실행하는 쪽에서 막아야 합니다.

## 어떻게 (이 앱에서)

- (기반) 권한별 검색(G3) · 개인정보(G2)
- 겹겹이: 글 검사(문 하나 · SELECT/WITH · 금지 낱말) → 읽기 전용 연결 + query_only → 허가 콜백(쓰기 거부 · 역할별 개인정보 열 거부 — 별칭 · 하위 질의 · * 도) → 시간 · 행 상한
- 관리자 역할은 서버가 확인한 관리자만, 위험 질의 시험(삭제 · 두 문 · ATTACH · PRAGMA · 개인정보 열 · 무한 재귀 · 정상 질의)
