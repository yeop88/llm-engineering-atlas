# 장기 메모리 — 기억 추출 · 시점 기록 · 연결 · 점수 검색 · 계층 · 통합 · 망각 · 여러 세션 평가 · 실측 (ME1~ME7)

화면은 `/memory/store`(기억 쌓기 · 갱신) · `/memory/recall`(기억 꺼내기 · 정리) · `/memory/eval`(여러 세션 평가), 코드는 `app/stages/memory/` 입니다. 기억은 DB 표(`mem_items` · `mem_links`, 마이그레이션 0020)에 둡니다.

```
대화 ─ 추출(규칙 + LLM, 같은 key 목록) → 한 문장 한 사실(key · 값 · 종류 · 중요도 · 일어난 날) (ME1)
   ↓ 갱신 규칙: 그대로 · 고치기(예전 값에 '언제까지' 남김) · 추가 (ME4)
   ↓ 저장 · 연결: 같은 key 이력 · 비슷한 기억 · 요약 ← 원래 기억 (ME2)
질문 ─ 점수 = 비슷함 · 최근 · 중요도 + 연결 확장, 과거 질문이면 이력까지 (ME3)
   ↓ 맥락 = [핵심 기억] 늘 + [관련 기억] 시점 표시 (ME6)
정리 ─ 오래된 사건 → 요약 · 보관, 쓰이지 않는 기억 → 망각 (ME5)
평가 ─ 여러 세션 대화 × 질문 6유형 × (전체 기록 · 메모리 · 없음) (ME7)
```

## 설계

- **한 문장 한 사실 · 같은 key.** 원문을 쌓으면 찾기도 갱신도 어렵습니다. 기억을 '무엇에 관한 것(key) · 값 · 문장' 으로 뽑습니다. 규칙(정규식)은 상담에 자주 나오는 것(이름 · 주소 · 보유 제품 · 선호 시간 · 수리 이력 · 연락처)을 빠르고 틀림없이 뽑고, LLM 은 규칙 밖의 사실까지 뽑습니다 — 둘 다 같은 key 목록을 써야 갱신 판단을 할 수 있습니다. '규칙 + LLM' 은 규칙이 맞힌 key 는 규칙을 믿고 LLM 이 더 찾은 것을 더합니다. 연락처는 가려서 남깁니다 — 기억 DB 도 개인정보 저장소입니다. 사건은 '3월 20일 · 어제 · 지난주' 를 말한 날 기준의 날짜로 풀어 '일어난 날' 로 둡니다(말한 날과 다름).
- **덮어쓰지 않고 시점을 남긴다.** 하나만 맞는 key(이름 · 주소 · 연락처 · 선호)에 다른 값이 오면, 예전 기억에 `valid_to`(언제까지 맞았나) · `superseded_by`(무엇으로 바뀌었나)를 남기고 새 기억을 만듭니다. 이사한 고객에게 예전 주소로 기사를 보내면 안 되고, 그렇다고 지워 버리면 '예전엔 어디 살았나'에 답하지 못합니다. 여럿이 쌓이는 key(보유 제품 · 수리 이력)는 추가하고, 같은 값이나 아주 비슷한 문장(코사인 0.92 이상)은 그대로 두고 쓰임만 갱신합니다.
- **연결.** 같은 key 의 이력 · 벡터가 가까운 기억(0.75 이상) · 요약과 원래 기억을 연결 표로 잇습니다. 하나를 찾으면 이어진 기억을 반 점수로 함께 꺼냅니다(1단계) — '그때 그 수리' 처럼 흩어진 기억을 한 번에 모으려는 것입니다(A-mem 의 연결 · 진화 설계를 참고한 아이디어, 코드는 새로 작성).
- **찾기는 비슷함만이 아니다.** 비슷함만 보면 몇 달 전 낡은 기억이 오늘 기억보다 먼저 나옵니다. 점수 = 비슷함 × 0.6 + 최근(마지막 쓰임 기준 반감기 30일 감쇠) × 0.2 + 중요도 × 0.2 로 고르고, 가중치는 화면에서 바꿔 비교합니다. 기본은 지금 맞는 기억만 — 질문이 과거를 물으면('예전' · '처음' · '전에' · '언제') 무효가 된 이력까지 넣고 '언제부터 언제까지' 를 붙입니다.
- **계층.** 핵심 기억(지금 맞는 이름 · 주소 · 연락처 · 선호 · 보유 제품)은 질문과 상관없이 맥락 맨 앞에 짧게(400자) 둡니다 — 검색에서 빠지면 안 되는 정보입니다. 나머지는 점수로 꺼내 쓰고(recall), 무효가 된 이력 · 합쳐진 사건은 보관(archive)으로 과거 질문에서만 씁니다. 계층별로 쓴 글자 수를 남겨 맥락 예산을 봅니다.
- **통합 · 망각.** 같은 key 의 오래된 사건(기본 60일, 3건 이상)은 요약 기억 하나로 합치고 원래 기억은 보관으로 옮깁니다(지우지 않음). 중요도 × 쓰임 감쇠가 문턱(0.05)보다 낮은 보관 · key 없는 기억은 지웁니다. 핵심 기억과 지금 맞는 단일 key 기억은 잊지 않습니다. 지우는 일이라 미리 보기를 먼저 보입니다.
- **전체 기록보다 나은지 같은 질문으로.** 고객마다 세션 4개(① 이름 · 주소 · 첫 제품 ② 선호 · 첫 수리 ③ 이사 · 두 번째 제품 ④ 선호 바뀜 · 두 번째 수리)를 정해진 씨앗으로 만들고 잡담을 섞어, 전체 기록이 실제 상담처럼 길어지게 합니다. 질문은 갱신(지금 주소 · 지금 선호 — 예전 값이 먼저 나오면 틀림) · 과거(처음 주소) · 누적(보유 제품 전부) · 시간(최근 수리 날짜) · 없는 기억(이메일 — 모른다고 해야 맞음) 6개. 정답 값이 답에 있는지로 채점하고 LLM 판정은 쓰지 않습니다. 전체 기록 · 메모리 · 없음(기준선)의 정답률과 맥락 글자 수를 함께 봅니다.
