# 분류 · 사진 진단 실측 (AS2 · AS4)

화면은 `/as/eval`(의도 · 긴급도 분류, 오류 사진 진단, 종단 평가, 실행 기록)입니다. 종단 평가 결과는 [AS 상담 흐름](../as1-intake/console.md#실측-문의-세트-종단-2026-10-21).

## AS2 의도 · 긴급도 분류

- **안전은 규칙으로 먼저.** 감전 · 찌릿 · 불꽃 · 스파크 · 화재 · 연기 · 타는 냄새 · 가스 냄새 · 누전이 있으면 분류기를 보지 않고 바로 상담원에게 넘깁니다. 분류기가 한 번이라도 틀리면 위험한 문의에 자동 답변을 하게 되므로 확률 모델에 맡기지 않습니다(맵 원칙).
- 긴급도 '높음'(누수 · 전원 안 켜짐 · 히터 오류)은 티켓 우선순위에 씁니다.
- **의도는 임베딩 제로샷**: 문의와 라벨 설명('고장: 제품이 작동하지 않거나 오류 코드가 뜨거나 …')의 유사도 — 의미 응용(A)의 분류와 같은 함수입니다. 라벨 붙은 문의가 없을 때부터 쓸 수 있습니다.
- **오류 코드 추출**: 매뉴얼의 알려진 코드만 뽑습니다('5G' · 'A4' 같은 일반 낱말을 코드로 오해하지 않게).

### 실측 (2026-10-20, run #294, 라벨 문의 48개, KURE-v1)

| 방법 | 정확도 | macro F1 |
|---|---|---|
| **제로샷**(라벨 설명) | **95.8%** | 0.933 |
| 학습 분류기(로지스틱 회귀, 5겹 교차검증) | 85.4% | 0.786 |

- 제로샷이 틀린 2개는 둘 다 반품 문의를 '배송'으로('받은 지 3일 됐는데 반품하고 싶어요', '단순 변심 반품 배송비는 누가 내요') — 배송 낱말이 겹칩니다.
- **학습 분류기가 더 나쁜 이유는 데이터가 적어서입니다.** 48개를 5겹으로 나누면 한 번에 38개로 학습하고, '설치'(5개) · '사용법'(9개)은 겹마다 몇 개뿐이라 재현율이 0.4 · 0.67 로 떨어졌습니다. 라벨이 수백 개 쌓이기 전까지는 제로샷이 낫고, 상담 기록(E5 피드백)으로 라벨이 쌓이면 다시 잽니다.
- 긴급도(규칙): 안전 재현율 · 정밀도 **5/5 · 5/5**. 처음 측정에서 '전원 버튼을 눌러도 아무 반응이 없어요'를 '높음'으로 못 잡아(전원과 증상 사이를 6자까지만 봄) 15자로 넓혔고, 그 뒤 48/48 입니다 — 같은 세트로 고친 것이라 이 48/48 은 독립 측정이 아닙니다.
- 코드 추출 14/15 — 놓친 1개('빨래 다 했는데 물이 그대로 차 있어요', 라벨 E4)는 글에 코드가 없는 문의라 맞는 결과입니다. 이런 문의는 사진(AS4)이나 증상 검색이 맡습니다.

## AS4 오류 사진 진단

- 비전 LLM 에게 표시창의 코드를 JSON(`{"code", "display", "seen"}`)으로 읽게 하고, **알려진 코드 목록에 맞춥니다**: 목록에 그대로 있으면 그대로, 없으면 비슷한 글자(O↔0 · B↔8 · I/l↔1 · S↔5 · Z↔2)를 바꿔 맞는 것이 있으면 고치고 '고쳤음'을 남깁니다.
- 모델이 `code` 를 비우고 `display` 에만 코드를 쓰는 경우가 있어(OE · d80 · HE 에서 관찰) `display` 에서도 알려진 코드를 찾습니다. JSON 이 아닌 글로 답하면 '읽지 못함'으로 처리합니다(예전에는 상담 전체가 오류로 끝났음).
- 시험 그림: 제품 앞판 + 어두운 표시창의 밝은 글자 + 버튼을 그리고, 어려운 판은 ±12° 기울기 · 흐림 · 빛 반사를 더합니다(`photo.make_test_image`).

### 실측 (2026-10-21, gemma-4-e4b + mmproj, 코드 12종 × 2장)

| 그림 | 정확도 | 목록 맞춤 전 | 맞춤으로 고친 수 | 장당 시간 | 실행 |
|---|---|---|---|---|---|
| 쉬운 판 | 24/24 | 24/24 | 0 | 3.2초 | #308 |
| 어려운 판(기울기 · 흐림 · 반사) | 24/24 | 24/24 | 0 | 4.3초 | #309 |

- `display` 보완을 넣기 전 같은 모델 측정(코드 12개 1장씩, 다른 시간대)은 9/12 — 놓친 3개는 모두 `code` 를 비우고 `display` 에만 코드를 쓴 경우였습니다. 위 측정에서는 모델이 `code` 칸을 모두 채워(맞춤 전 24/24) 보완이 쓰일 일이 없었습니다. 즉 같은 모델 · 같은 프롬프트에서도 출력 형식이 흔들리며, 보완은 그 흔들림에 대한 대비입니다.
- 한계: 만든 그림이라 글자가 크고 또렷합니다(흐림 · 반사를 넣어도). 실제 사진(작은 표시창 · 손떨림 · 7-세그먼트 글꼴)은 더 어렵고, '맞춤으로 고친 수' 0 은 비슷한 글자 혼동이 이 시험에서 나오지 않았다는 뜻입니다. 실제 고객 사진 세트를 모아 다시 재야 합니다.
