# AS 상담 흐름 — 접수 · 답변 · 조치 안내 · 검증 (AS1 · AS3 · AS5 · AS6)

화면은 `/as/console`(상담 창)입니다. 흐름은 `app/stages/as_service/flow.py`, 답변은 연결 계층의 서비스 답변(`serve.answer_once`)이라 가드레일 · 요청 기록이 다른 화면과 똑같이 붙습니다.

```
AS1 접수(글 · 사진 · 음성) → AS2 분류(의도 · 긴급도 · 코드) ─ 안전 → 바로 상담원(AS7)
                                  └ 사진 → AS4 코드 읽기 ─┐
AS3 매뉴얼 · FAQ 답변(제품 범위 검색 · 의미 캐시) ←──────┘ → AS5 조치 안내(고장이면 번호 단계)
→ AS6 검증(근거 일치 · 코드 일치 · 정책 · 다른 모델 근거) → '해결되셨나요?' → AS8 → 미해결이면 AS7
```

## 예시 자료

실제 회사 · 제품과 관계없는 가상 자료(`app/stages/as_service/presets/as_demo.json`)입니다: 드럼세탁기 WM-200 · 통돌이 WM-100 · 건조기 DR-300 매뉴얼(오류 코드별 조치) + 고객센터 FAQ, 라벨 붙은 문의 48개(의도 · 긴급도 · 제품 · 코드), 사진 시험용 코드 12개. 상담 창의 '예시 자료 준비'가 컬렉션 · 청크 세트(BM25) · 의미 인덱스(KURE-v1)를 만듭니다. 매뉴얼마다 메타 `product_model` 을 붙여 둡니다.

## 설계

- **AS1 접수**: 상담 한 건 = 세션(고객 · 제품 모델 · 경로 · 대화 · 분류 · 티켓). 사진은 최대 3장(첫 장으로 코드 읽기), 음성은 `STT_URL`(OpenAI 호환 `/audio/transcriptions`, 예: whisper.cpp server)이 있을 때 글로 옮깁니다.
- **AS3 검색 범위 = 고객 제품 문서 + 모델 구분 없는 공통 문서(FAQ).** 메타 필터(D6)의 `product_model` 은 모델이 없는 문서(FAQ)까지 빼므로 상담 흐름이 허용 문서를 직접 고릅니다 — FAQ 가 빠지면 배송 · 환불 문의에 답을 못 합니다.
- 오류 코드가 있으면 검색 질문에 `(오류 코드 E4)` 를 붙입니다. 고객이 코드만 말하거나 문장에 묻혀 있어도 BM25 가 코드 항목을 잡게.
- **의미 캐시**: 같은 제품 범위에서 질문 임베딩 유사도 0.93 이상이고 **검증을 통과한 답만** 재사용합니다(거절 아님 · 근거 일치 80% 이상 · 정책 통과 · 코드 일치). 기준을 낮추면 다른 질문에 같은 답이 나갑니다. 사진이 붙은 문의는 캐시하지 않습니다. 컬렉션에 문서가 새로 올라오거나 글이 바뀌면(OCR · 정제 · 가리기 · 폴더 동기화가 남기는 바뀐 시각) 그보다 앞선 캐시를 모두 버리고, 근거 문서가 지워진 캐시도 버립니다 — 매뉴얼을 고쳐도 옛 답이 계속 나가면 캐시가 틀린 답을 퍼뜨리기 때문입니다. 새 문서가 다른 질문의 답도 바꿀 수 있어 근거 문서가 아니라 컬렉션 단위로 봅니다.
- **AS5 조치 안내**: 고장 의도면 '번호 단계로, 분해 · 전기 작업은 방문 수리를 권하라'는 지시를 **시스템 프롬프트에** 붙입니다. 처음엔 질문 끝에 붙였는데, 그러면 검색 · 관련성 검증이 지시문까지 질문으로 읽었습니다. 위험한 자가 조치 안내는 고객 지원 출력 정책(G4)이 막고 상담원에게 넘깁니다.
- **AS6 검증 — 문장 관련성 대신 오류 코드 일치.** 조치 단계 문장('전원 플러그를 뽑습니다')은 질문('E4 가 떠요')과 의미가 멀어 문장 관련성이 0.43~0.56 으로 늘 기준(0.68) 아래였습니다(실측, KURE-v1) — 모든 고장 답이 '관련 없음'이 됩니다. 그래서 조치 안내 답은 연결 계층의 문장 관련성 검사를 끄고, **근거 글에 고객의 코드가 있는지**로 질문에 맞는 답인지 봅니다. 고객 제품 자료에 그 코드가 없으면(WM-100 은 배수 오류가 E4 가 아니라 OE) 답 끝에 '자료에 그 코드가 없으니 표시창을 다시 확인해 달라'고 알립니다.
- **다른 모델 근거 경고**: 근거 문서의 `product_model` 이 고객 제품과 다르면 답에 경고를 붙입니다. 근거에 있어도 다른 모델의 조치는 틀린 답입니다(WM-100 에는 앞면 배수 필터가 없음).
- 거절(자료에 없음) · 정책 막음이면 티켓을 만들어 상담원에게 넘기고, 그 밖에는 '해결되셨나요?'로 끝냅니다.

## 실측: 문의 세트 종단 (2026-10-21)

라벨 문의 앞 24개(고장 22 — 안전 5 · 높음 3 포함, 사용법 2)를 상담 흐름에 그대로 넣었습니다. 방어 enforce, LLM gemma-4-e4b(로컬), 혼합 검색(KURE-v1 + BM25) 상위 4개, 캐시 끔.

- **제품 범위를 끄면 맞는 매뉴얼은 여전히 잡히지만(17/17), 다른 모델 매뉴얼이 거의 늘 함께 들어옵니다.** 세 제품의 오류 항목이 비슷한 말('배수 · 필터 · 전원')을 써서, 상위 4개 중 나머지 자리를 다른 모델이 채웁니다. 답은 그 섞인 근거로 쓰이므로 다른 모델 조치가 나올 수 있고, 근거 글이 길어져 5.6초 느려졌습니다.
- '근거 일치'가 끈 쪽이 조금 높은 것은 근거가 많아 맞는 문장을 찾기 쉬워서이고, 맞는 제품의 답인지는 말해 주지 않습니다 — 그래서 모델 불일치를 따로 봅니다.
- 거절 1건('전원 버튼을 눌러도 아무 반응이 없어요')은 매뉴얼에 그 증상 항목이 없어 상담원에게 넘어갔습니다(맞는 처리).
- 첫 집계에서 '맞는 문서'가 0.773 으로 나왔는데, 검색 없이 바로 이관한 안전 문의 5건을 분모에 넣은 집계 오류였습니다(이관이 잘될수록 점수가 떨어짐). 고친 뒤 위 표입니다.

한계: 자료가 작고(문서 4개) 가상 제품이며, 문의도 매뉴얼을 보고 쓴 것이라 실제 고객 표현보다 쉽습니다.
