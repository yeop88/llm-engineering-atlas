# BM5 · 연속 배칭 (Continuous batching)

**상태: ✅ 구현됨** — 끝난 요청 자리에 바로 새 요청을 넣어 GPU 를 쉬지 않게 한다

## 원리

연속 배칭은 묶음 전체가 끝나길 기다리지 않고, 토큰 단위로 끝난 요청을 빼고 새 요청을 넣는 스케줄링입니다. 처리량이 오르고 짧은 요청이 긴 요청을 기다리지 않습니다.

## 왜 하는가

고정 묶음은 가장 긴 요청이 끝날 때까지 나머지 자리가 놉니다. 동시 요청이 많을수록 그 낭비가 커집니다.

## 어떻게 (이 앱에서)

- (기반) 동시 부하 실측(S4) · 페이지 KV(BM4)
- 걸음 시간 모형(기본 + 자리당 + 미리 채우기 토큰당)으로 같은 포아송 도착을 고정 묶음 · 연속 배칭 — 처리량 · 대기 포함 지연 · 첫 토큰 · 자리 쓰임
- llama-server 슬롯 수(-np) × --cont-batching / --no-cont-batching 을 같은 동시 부하로 실측
