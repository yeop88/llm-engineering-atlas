# BM5 · 연속 배칭 (Continuous batching)

**상태: ⬜ 예정** — 끝난 요청 자리에 바로 새 요청을 넣어 GPU 를 쉬지 않게 한다

## 원리

연속 배칭은 묶음 전체가 끝나길 기다리지 않고, 토큰 단위로 끝난 요청을 빼고 새 요청을 넣는 스케줄링입니다. 처리량이 오르고 짧은 요청이 긴 요청을 기다리지 않습니다.

## 왜 하는가

고정 묶음은 가장 긴 요청이 끝날 때까지 나머지 자리가 놉니다. 동시 요청이 많을수록 그 낭비가 커집니다.

## 어떻게 (이 앱에서)

- (기반) 동시 부하 실측(S4)
- (예정) 고정 묶음 vs 연속 배칭 스케줄러 · 처리량 · 대기 시간 · 서버 슬롯 실측
