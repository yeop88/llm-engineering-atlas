# 합성 데이터 — 부족 분석 · 전략 · 생성 · 다양성 · 중복 · 누수 거르기 · 검토 표본 · 실제 질문으로 효과 평가 (SD1~SD8)

화면은 `/synthetic/data`(합성 데이터), 코드는 `app/stages/synthetic/`, 묶음은 `data/synthetic/<이름>.jsonl` · `.meta.json` 입니다.

```
유형이 붙은 실제 질문 → 학습용(적고 치우치게) · 시험용(생성 · 학습에 안 씀)
  → 유형별 학습 수 · 교차 검증 재현율 → 부족 유형 · 이유 (SD1) → 유형마다 전략: 틀 · 쉬운 말 바꿔 쓰기 · 이어 붙이기 · LLM (SD2)
  → 학습용 근거 · 질문만 원본으로 생성, 만든 방법 · 원본 id 기록 (SD3)
  → 다양성: 평균 쌍 유사도 · 2-gram · 첫 어절 반복, 먼 점 고르기 (SD4)
  → 거의 같은 것 · 시험용과 비슷한 것(누수) · 개인정보 빼기 (SD5) → 유형이 고른 검토 표본 · 오류율 95% 구간 → 통과 · 반려 (SD6)
  → 실제만 · 실제 + 합성(거르기 전 · 후) · 합성만 · 실제 + LLM 합성으로 분류기 학습 (SD7)
  → 시험용 실제 질문 · 합성 시험 질문으로 평가 (SD8)
```

## 설계

- **과제는 질문 유형 분류입니다.** 법률 질문 7유형(사실 · 바꿔 말하기 · 조건 · 상황 · 긴 상황 · 답 없음 · 여러 질문)은 답하는 방법(라우팅 · 거절 · 근거 수)을 정하는 신호입니다. 학습이 가벼워서(글자 n-gram TF-IDF + 로지스틱 회귀) 합성 데이터의 효과를 이 PC 에서 씨앗 여러 개로 되풀이해 잴 수 있습니다. 같은 흐름은 후학습(LoRA SFT) 데이터에도 그대로 쓸 수 있습니다.
- **실제 데이터가 부족한 상황을 만들어 시작합니다(SD1).**
  - 평가 세트(eval_set 5, 248문항)를 나눕니다. 학습용은 유형마다 12 · 12 · 12 · 6 · 6 · 2 · 1건으로 적고 치우치게 둡니다(조건 2 · 여러 질문 1). 시험용은 나머지 197건입니다.
  - 부족 판단은 두 가지입니다. 학습 수가 8건 미만이거나, 학습용만으로 접어 나눈 교차 검증 재현율이 60% 미만이면 부족으로 봅니다.
- **부족한 것만 만듭니다(맵 원칙).** 부족 유형에만 전략을 적용합니다.
  - 형식이 유형을 정하는 것(조건 '만약 …라면', 상황 '제가 … 했는데')은 틀로 만듭니다.
  - 말투가 정하는 것(바꿔 말하기)은 법률 용어를 일상 말로 바꿉니다(근로자 → 직원, 임차인 → 세입자).
  - 여러 질문은 두 물을 거리를 이어 붙입니다.
  - LLM 바꿔 쓰기는 같은 자리에 끼우는 선택지입니다.
- **원본은 학습용뿐입니다(SD3).** 시험용 질문의 근거로 질문을 만들면, 시험 문제를 보고 공부한 것이 됩니다. 생성 원본은 학습용 실제 질문의 근거 문장 · 질문뿐이고, 질문마다 만든 방법과 원본 id 를 남깁니다. 거르기(SD5)에서도 시험용 질문과 글자가 비슷한(0.6 이상) 합성 질문을 한 번 더 뺍니다.
- **틀이 글을 깨뜨리지 않게 했습니다.** 처음에는 물을 거리를 글자 수(40자)로 잘라 '…단서에 따은 무엇을 뜻하나요?'가 나왔습니다. 조사도 틀에 박아 두어 '채무자 소유은'이 나왔습니다. 지금은 어절 단위로 끊고(조사로 끝나는 어절에서 조사를 떼고 멈춤), 받침을 보고 은/는 · 이/가를 고릅니다.
- **많이보다 다양하게(SD4).** 유형마다 60건을 만들고, 글자 n-gram 코사인으로 가장 덜 비슷한 것부터 25건을 고릅니다(먼 점 고르기). 평균 쌍 유사도 · 서로 다른 2-gram 몫 · 첫 3어절 반복을 거르기 전후로 남깁니다.
- **검토는 구간으로 판정합니다(SD6).** 유형이 고르게 섞인 표본(기본 20건)에 사람이 '쓸 만함 · 아님'을 표시합니다. 통과 기준은 오류율 윌슨 95% 구간의 위 끝 20% 미만입니다. 표본 20건에 오류 0건이어도 위 끝은 16% 이므로, 오류가 하나만 나와도 반려 쪽으로 기웁니다. 적은 표본으로 쉽게 통과시키지 않으려는 것입니다.
- **평가는 실제 질문으로 합니다(SD8).** 맵 원칙 '합성 평가 점수를 믿지 않는다'를 숫자로 보이려고, 같은 분류기를 합성 시험 질문(같은 틀 · 다른 씨앗)으로도 잽니다.

## 실측

2026-10-23, eval_set 5(법률 7유형 248문항), 나누기 씨앗 0~4(씨앗마다 부족 분석부터 다시), 규칙 생성(LLM 없음) · 유형마다 60건 생성 → 25건 고르기.

| 학습 데이터 | 학습 수(평균) | 실제 시험 정확 (5씨앗 범위) | 실제 유형 평균 재현 | 합성 시험 정확 |
| --- | --- | --- | --- | --- |
| 실제만 | 51 | 34.8% (30.5~36.5) | 32.7% | 36.6% |
| 실제 + 합성(거르기 전) | 387 | 36.6% (31.0~41.6) | 35.0% | 92.6% |
| 실제 + 합성(거른 뒤) | 191 | **37.8%** (31.5~41.1) | 36.0% | 91.8% |
| 합성만(거른 뒤) | 140 | 31.5% (27.9~36.5) | 27.2% | 80.0% |

유형별 실제 재현(실제만 → 실제 + 합성(거른 뒤)):

| 사실 | 바꿔 말하기 | 조건 | 상황 | 긴 상황 | 답 없음 | 여러 질문 |
| --- | --- | --- | --- | --- | --- | --- |
| 63.8 → 62.5% | 43.2 → 42.6% | 0 → 11.0% | 70.0 → 77.8% | 28.2 → 10.6% | 23.3 → 47.5% | 0 → 0% |

부족 분석(씨앗 0): 여러 질문(1건 · 재현 0%) · 조건(2건 · 0%) · 바꿔 말하기(재현 25%) · 긴 상황(6건) · 답 없음(6건) · 사실(재현 50%)이 부족으로 잡혔고, 상황(12건 · 83%)만 충분했습니다. 거르기에서 뺀 것은 0건이었습니다(중복 · 누수 · 개인정보 모두 0).

해석:

- **합성 시험 점수는 믿을 수 없습니다.** 합성을 섞어 학습한 분류기가 합성 시험 질문은 92% 맞히지만, 실제 질문은 38% 입니다. 합성 질문은 같은 틀에서 나와 서로 닮았기 때문에, 틀을 외우면 합성 시험은 쉽게 풀립니다. 합성 데이터의 효과를 합성 데이터로 재면 54%p 를 부풀리게 됩니다.
- **규칙 생성의 실제 효과는 작습니다.** 실제만 34.8% → 실제 + 합성(거른 뒤) 37.8% 로 +3%p 지만, 씨앗 사이 범위(30~42%) 안입니다. 효과가 '있다'고 말할 수 없습니다. 거르기(다양성 고르기)는 학습 수를 절반으로 줄이고도 거르기 전보다 조금 나았습니다(36.6 → 37.8%).
- **틀이 유형의 겉모습만 배우게 합니다.**
  - 답 없음 재현은 23 → 48% 로 올랐습니다. 틀('…의 구체적인 금액 기준은 얼마인가요?')이 실제 답 없음 질문의 말투와 닮아서입니다.
  - 긴 상황은 28 → 11% 로 떨어졌습니다. 긴 상황 틀이 한 가지 말투뿐이라 '그 말투 = 긴 상황'을 배우고, 다른 말투의 실제 긴 상황 질문을 상황으로 보냈습니다.
  - 조건 · 여러 질문은 여전히 0~11% 입니다. 실제 조건 질문의 형식이 틀보다 훨씬 다양합니다(금액 계산이 든 질문 등).
  - 그래서 다음은 말투가 다양한 LLM 바꿔 쓰기를 같은 흐름으로 재는 것입니다.
- **합성만으로는 실제만보다 못합니다(31.5%).** 실제 질문 51건이 합성 140건보다 낫습니다. 합성은 실제를 대신하지 못하고 보탤 뿐입니다.

**LLM 바꿔 쓰기 비교 (run #369)** — 나누기 씨앗 0~2, 부족 유형마다 gemma-4-E4B 에 같은 유형 예 2개 + 학습용 근거 주제 8개를 주고 한 번에 8개씩, 거른 뒤 씨앗당 88~113개

| 학습 데이터 | 학습 수(평균) | 실제 시험 정확 (3씨앗 범위) | 합성 시험 정확 |
| --- | --- | --- | --- |
| 실제만 | 51 | 34.3% (30.5~36.5) | 33.6% |
| 실제 + 규칙 합성(거른 뒤) | 184 | 36.6% (31.5~41.1) | 91.8% |
| 실제 + LLM 합성(거른 뒤) | 150 | **37.1%** (35.0~38.6) | **43.8%** |

| 유형별 실제 재현 | 사실 | 바꿔 말하기 | 조건 | 상황 | 긴 상황 | 답 없음 | 여러 질문 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 실제 + 규칙 합성 | 60.4 | 34.4 | 10.0 | 80.9 | 5.9 | 55.6 | 0 |
| 실제 + LLM 합성 | 57.3 | 25.8 | 10.8 | 66.7 | **47.1** | 32.0 | 0 |

- **LLM 합성도 실제 정확을 거의 올리지 못합니다(34.3 → 37.1%).** 규칙 합성과 같은 수준이고 차이는 씨앗 범위 안입니다. 다만 범위가 좁아(35~39%) 씨앗에 덜 흔들립니다.
- **LLM 합성은 틀을 외우게 하지 않습니다.** 같은 분류기의 합성 시험 정확이 규칙 합성에서는 92% 지만, LLM 합성에서는 44% 로 실제(37%)에 가깝습니다. LLM 이 만든 질문은 말투가 다양해 '이 틀 = 이 유형'을 배울 수 없기 때문입니다. 합성 평가를 믿으면 안 되는 이유가 규칙 합성에서 특히 크다는 뜻입니다.
- **유형마다 강점이 다릅니다.** 긴 상황은 LLM 합성이 47% 로 크게 낫고(규칙 6%), 답 없음은 규칙이 낫습니다(56% vs 32%). 규칙의 '구체적인 금액 기준은 얼마인가요?' 틀이 실제 답 없음 질문과 닮았기 때문입니다. 유형마다 전략을 고르는 SD2 의 설계가 맞다는 근거입니다.
- 시간: LLM 생성이 씨앗당 약 10분(유형 6개 × 3번 호출)입니다. 규칙 생성은 1초 안입니다.

한계:

- 분류기가 글자 n-gram 이라 유형의 겉모습(말투 · 길이)만 봅니다. '답 없음'은 말투가 아니라 '근거에 답이 있나'로 정해지므로, 이 분류기로는 원래 잘 맞힐 수 없는 유형입니다.
- 검토(SD6)는 사람의 표시가 필요해 이 실측에 넣지 않았습니다. 거른 합성 질문 중에는 여전히 어색한 것('구 소득세법 시행령 제155조 제1항 제2호는 어떻게 판단되며, …')이 있습니다.
