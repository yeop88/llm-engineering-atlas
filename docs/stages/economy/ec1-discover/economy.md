# 에이전트 경제 · 거래 — 흉내 시장 · 흉내 장부로 찾기 · 비교 · 위임 · 승인 · 에스크로 · 검증 · 정산 · 분쟁, 공격 시나리오 시험 (EC1~EC8)

화면은 `/economy/ledger`(거래 규칙 · 흉내 장부), 코드는 `app/stages/economy/` 입니다. 실제 결제는 하지 않습니다. 흉내 시장(`presets/market.json`)과 흉내 장부로 규칙만 시험합니다.

```
일(번역 · OCR · 배송 접수) → 기능으로 찾기 (EC1) → 요구로 거르고 품질 대비 가격으로 비교 (EC2)
  → 위임 검사: 기능 · 상대 · 건당 · 월 한도 · 기한 (EC3) → 사람 승인: 5,000원 초과 · 처음 상대, 승인 금액 ≠ 결제 금액이면 막음 (EC4)
  → 에스크로에 묶기(같은 거래 id 한 번만) (EC5) → 납품 · 받기 기준 검증 (EC6)
  → 통과: 판매자에게 풀기 · 해시 사슬 영수증 (EC7) / 불합격: 환불 조건대로 · 미납품은 전액 (EC8)
시험: 정상 일 + 공격(한도 넘기 · 월 한도 · 위임 밖 상대 · 이중 요청 · 승인 뒤 값 바꾸기 · 납품 안 함 · 엉터리 결과)을 반씩 섞어,
      규칙 있는 에이전트와 규칙 없는 에이전트(가장 싼 것을 바로 결제)를 같은 씨앗으로
```

## 설계

- **돈은 되돌리기 어려운 행동입니다.** 그래서 규칙을 정상 흐름이 아니라 깨려는 흐름으로 시험합니다. '승인 없는 결제 0 · 예산 초과 0 · 위임 밖 결제 0 · 이중 결제 0 · 검증 없이 낸 돈 0'은 공격이 섞여도 지켜져야 의미가 있습니다.
- **위임(mandate)을 결제 전에 검사합니다(EC3).** 위임에는 맡긴 사람(고객지원팀) · 에이전트 · 허용 기능 · 허용 상대 목록 · 건당 한도(10,000원) · 월 한도(150,000원) · 기한이 있습니다. 하나라도 어기면 결제하지 않고 어긴 것을 남깁니다.
- **사람 승인은 '무엇을 승인했나'까지 묶습니다(EC4).** 5,000원을 넘거나 처음 거래하는 상대면 사람 승인을 받습니다. 승인 뒤 판매자가 값을 올리면(승인한 금액 ≠ 결제 금액) 막습니다. 승인을 '거래를 해도 된다'로만 두면, 승인한 것과 다른 것이 결제되는 틈(확인 시점과 사용 시점의 차이)이 생깁니다.
- **결과를 확인한 뒤 냅니다(EC5~EC7).** 돈을 판매자에게 바로 보내지 않고 에스크로에 묶고, 납품 · 받기 기준을 검증한 뒤에 풉니다. 불합격이면 판매자의 환불 조건대로 돌려받습니다(전액 · 50% · 없음). 납품 자체가 없으면 조건과 상관없이 전액입니다.
- **장부는 복식 기입 · 정수 원 · 해시 사슬입니다.**
  - 모든 기입은 한 계정에서 빼고 다른 계정에 더합니다. 충전한 돈과 모든 계정 잔액의 합이 같아야 합니다.
  - 금액은 원 단위 정수입니다. 부동소수 반올림으로 돈이 새지 않게 하려는 것입니다.
  - 같은 거래 id 는 한 번만 묶습니다(재시도 · 중복 요청의 이중 지불 방지).
  - 기입마다 앞 기입의 해시를 넣어, 한 줄을 고치면 뒤가 모두 어긋납니다.
- **흉내인 것을 밝힙니다.** 시장 · 판매자(신뢰도 · 품질 확률로 납품) · 사람 승인(요청의 90% 를 받아들임)은 흉내입니다. 실제 결제 · 실제 에이전트 카드는 쓰지 않습니다. 시험하는 것은 규칙이 공격을 막는가입니다.

해석:

- **규칙 있는 에이전트는 공격이 섞여도 지켜야 할 것을 모두 0 으로 지켰습니다.** 같은 일에서 규칙 없는 에이전트는 쓴 돈의 52%(2,447,620원)를 엉터리 결과 · 미납품에 잃었습니다. 막은 것은 모두 결제 전이었고, 돈이 나간 뒤에 돌려받는 일은 검증에 걸린 경우(환불 990,000원)뿐이었습니다.
- **승인 요청이 많습니다(일 800건에 484번).** 처음 거래하는 상대마다 승인을 받기 때문입니다. 실제 운영에서는 사람의 부담이 크므로, '한 번 승인한 상대 · 금액 범위는 다시 묻지 않음'처럼 승인 기억을 두는 것이 다음 할 일입니다. 다만 그 기억이 범위 밖 결제의 틈이 되지 않게 위임 검사는 매번 합니다.
- **정상 일도 환불됩니다(49건).** 판매자가 확률적으로 엉터리 결과를 내기 때문입니다. 에스크로 덕에 정상 흐름에서도 돈을 잃지 않습니다.

한계: 시장 · 판매자 · 승인자는 흉내입니다. 실제 결제망 · 서명 · 위임 증명(전자 서명된 mandate)은 다루지 않습니다.
