# 사용자 피드백 · 개선 루프 (E5 · E8)

화면은 `/evalops/feedback`(피드백 요약 · 싫어요 받은 답 · 실패 유형)이고, 답변 화면(`/rag/answer`) 답 아래에 피드백 버튼이 있습니다.

## E5 피드백

- 답마다 좋아요 · 싫어요, 싫어요면 이유(근거 없음 · 지어냄, 질문과 상관없음, 숫자 · 사실이 틀림, 답을 안 함, 덜 답함, 위험 · 부적절, 기타)와 메모. 답변 스트림의 `done` 이벤트가 요청 기록 번호(`trace_id`)를 주고, 피드백은 그 기록에 붙습니다.
- **자동 판정과 사람 판정의 일치**: 근거 일치 · 관련성으로 자동 판정한 '좋은 답'과 사람의 좋아요 · 싫어요를 교차표로 봅니다. 사람은 싫어요인데 자동은 좋다고 한 답이 자동 판정이 놓친 것 — 검증 기준(2 RAG 의 근거 일치 · 관련성 문턱)을 고칠 근거가 됩니다.

## E8 개선 루프

요청 기록을 실패 유형으로 나누고, 유형마다 갈 곳을 정합니다.

| 유형 | 판단 | 보낼 곳 |
|---|---|---|
| 검색 실패 | 결과 0개, 또는 사람이 '근거 없음' | 자료 보강 목록(CSV) · 평가 세트 |
| 인용 · 근거 실패 | 없는 인용 번호 · 자료에 없는 조문 번호 · 근거 일치 < 0.5 · 사람이 '사실 틀림' | 평가 세트 |
| 질문과 상관없는 답 | 관련 없는 문장이 있음 · 사람이 '질문과 다름' | 평가 세트 |
| 과도한 거절 | 거절했는데 싫어요 | 평가 세트(답이 있는 질문으로) |
| 정책 위반 · 차단 | 차단 · 출력 정책 위반 | 레드팀 · 정책 점검 |

평가 세트로 보낸 질문은 '검토 전' 문항으로 들어가 사람이 정답 문서를 붙이고 통과시킬 때 기준이 됩니다.

## 실측: 첫 보고에서 찾은 것 (2026-10-21, 기록 174건)

이번 실측 기록(레드팀 · AS · A/B)으로 루프를 처음 돌렸을 때, 실패로 분류된 108건 중 두 묶음은 **서비스가 아니라 판정 쪽 문제**였습니다.

1. **'질문과 상관없는 답' 66건 중 42건이 AS 조치 안내.** 번호 단계 문장은 질문과 의미가 멀어 문장 관련성 검사가 늘 '관련 없음'을 냅니다(0.43~0.56, 기준 0.68). → AS 조치 안내는 문장 관련성을 끄고 오류 코드 일치로 판정하게 바꿨습니다([AS 상담 흐름](../../as-service/as1-intake/console.md)). 이전 기록은 그대로 남습니다.
2. **'검색 실패' 18건이 모두 권한이 막은 질문.** 일반 그룹 사용자의 인사 기록 질문은 권한(G3)이 후보를 0개로 만들어 거절하는데, 루프가 이를 검색 실패로 셌습니다. → 권한으로 후보가 0개가 된 기록은 검색 실패로 세지 않게 고쳤고(18 → 6), 테스트로 고정했습니다.

루프는 고칠 것을 찾는 장치이므로, 분류가 틀리면 엉뚱한 것을 고치게 됩니다. 새 유형의 답(조치 안내 · 권한 거절)이 생길 때마다 분류부터 확인합니다.
