# E3 · 트레이싱 (Tracing)

**상태: 🟡 기초 있음** — 질문마다 단계 · 시간 · 토큰 · 결정(라우팅 · 도구)을 기록해 한 요청을 끝까지 따라가 본다

## 원리

트레이스는 요청 하나가 거친 단계(검색 · 재정렬 · 라우팅 · 에이전트 행동 · 답변 · 검증)를 시간 순서로 남긴 기록입니다. 단계마다 입력 · 출력 요약 · 시간 · 토큰을 남기면 느리거나 틀린 원인을 찾을 수 있습니다.

## 왜 하는가

평균만 있으면 원인을 못 찾습니다 — 에이전트 측정에서 한 질문이 20분 걸린 이유를 질문별 기록이 없어 찾지 못했습니다.

## 어떻게 (이 앱에서)

- (있음) 연결 실행의 단계별 상태 · 시간, llama-server 읽기 · 쓰기 시간, 에이전트 단계 기록, 연결 비교의 질문별 기록
- (예정) 모든 서비스 요청에 추적 id 와 단계 기록 저장(OpenTelemetry 형식 호환), 느린 요청 · 실패 요청 찾기 화면

## 화면

- 아직 테스트 화면이 없습니다. 단계 소개는 앱의 `/stages/ev_tracing` 에서 볼 수 있습니다.

## 앞으로 할 일

- 요청 단위 트레이스 저장
- 느린 · 실패 요청 화면
