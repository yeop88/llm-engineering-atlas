# A/B 실험 (E7)

화면은 `/evalops/experiments`(실험 목록 · 만들기 · 보고 · 질문 하나 · 기록 재생 · 멈춤)입니다.

## 설계

- 실험 = 컬렉션 + 두 팔(A · B). 팔마다 검색 설정 · LLM · 근거 수 · 근거 압축 · 최대 토큰.
- **배정은 키의 해시로 고정**: '실험 번호:사용자(또는 세션) 키'를 sha256 해시해 0~1 로 바꾼 값이 비율(`split`)보다 작으면 B, 아니면 A. 같은 사용자는 늘 같은 쪽을 보므로, 한 사람이 질문마다 다른 답 방식을 겪지 않고 피드백이 한 팔에 모입니다. 무작위가 아니라 해시인 이유: 다시 계산해도 같은 배정이 나와 저장할 것이 없습니다.
- 실험 답변도 서비스 답변(`serve.answer_once`)이라 가드레일 · 요청 기록이 같고, 기록에 실험 · 팔이 남아 대시보드 · 피드백에서 팔별로 봅니다.
- **기록 재생**: 평가 세트 질문을 실제 요청처럼 흘려보내(배정 키 = 질문) 출시 전에 미리 비교합니다.
- **판정**: 팔별 근거 일치 · 관련성 · 거절률 · 좋아요 비율 · 지연 · 비용과 B − A 차이의 부트스트랩 95% 구간. 품질 차이가 구간 안에서 불확실하면 '품질 차이 불확실'로 적고, 유의한 것만 '좋아짐 · 나빠짐 · 빠름'이라고 씁니다.

## 실측: 근거 압축 120문항 재측정 (2026-10-21, 실험 #2)

아래 20문항 측정(실험 #1)은 팔마다 10개 안팎이라 품질 차이를 판단할 수 없어, 같은 설정으로 질문을 120개(평가 세트 #7, 시드 1)로 늘려 다시 쟀습니다(배정 A 60 · B 60, 약 66분).

| 지표 | A 근거 그대로 | B 청크당 3문장 | B − A (95% 구간) |
|---|---|---|---|
| 입력 토큰 / 답 | 2,483 | 1,562 | −37% |
| 평균 지연 | 42.8초 | 23.5초 | **−19.3초 [−23.6, −15.3] 유의** |
| p95 지연 | 62.0초 | 43.6초 | |
| 근거 일치 | 0.895 | 0.911 | +0.017 [−0.070, +0.107] 불확실 |
| 질문 관련성 | 0.650 | 0.741 | +0.092 [−0.043, +0.228] 불확실 |
| 거절률 | 1.7% | 0% | −1.7%p |

판정: **품질 차이 불확실 · B 가 유의하게 빠름.**

- **20문항에서 보였던 품질 하락(근거 일치 −0.098)은 표본이 작아 생긴 흔들림이었습니다.** 120문항에서는 오히려 B 가 조금 높고(+0.017), 구간이 0 을 지나 '차이 없음'에 가깝습니다. 20문항짜리 결과로 압축을 버렸다면 틀린 결정이었습니다 — 질문 수를 늘려 다시 재는 것이 이 단계의 목적입니다.
- 지연은 두 측정 모두 유의하게 줄었습니다(−16.3초 → −19.3초). 로컬 LLM 의 시간 대부분이 근거를 읽는 데 들어서, 근거 글을 37% 줄인 만큼 그대로 빨라집니다.
- 2 RAG 의 압축 실측(같은 질문을 두 설정으로 답해 짝지어 본 것, 품질 −10)과 결론이 다릅니다. 그쪽은 정답 문장 인용(정답 근거가 답에 들어갔나)으로 쟀고, 여기는 근거 일치 · 질문 관련성(답이 근거에 맞나)이라 재는 것이 다릅니다 — 압축은 '답이 근거와 어긋나게' 만들지는 않지만 '정답 문장을 버릴' 수는 있습니다.

## 실측: 근거 압축 20문항 (2026-10-21, 실험 #1)

법률 컬렉션, KURE-v1 하이브리드 상위 5개, gemma-4-e4b(로컬). A = 근거 5개 그대로, B = 근거 5개를 두되 청크마다 질문과 형태소가 많이 겹치는 문장 3개만 남김(`compress_keep=3`, 2 RAG 의 근거 압축). 평가 세트 #7 질문 20개를 재생했습니다(배정 A 9 · B 11).

| 지표 | A 근거 그대로 | B 청크당 3문장 | B − A (95% 구간) |
|---|---|---|---|
| 입력 토큰 / 답 | 2,433 | 1,522 | −37% |
| 평균 지연 | 41.8초 | 25.5초 | **−16.3초 [−26.1, −6.7] 유의** |
| 근거 일치 | 0.984 | 0.886 | −0.098 [−0.280, +0.032] 불확실 |
| 질문 관련성 | 0.820 | 0.700 | −0.120 [−0.421, +0.195] 불확실 |
| 거절률 | 0 | 0 | 0 |

판정: **품질 차이 불확실 · B 가 유의하게 빠름.**

- 압축은 입력 토큰을 37% 줄여 16초 빨랐습니다. 품질 지표는 둘 다 B 가 낮지만 팔마다 10개 안팎이라 구간이 넓어 결론을 낼 수 없습니다 — 근거 일치 −0.1 이 사실이라면 받아들이기 어려운 크기이므로, 출시 전에 질문을 늘려(100개 이상) 다시 재야 합니다.
- 2 RAG 의 근거 압축 실측(지연 −19% 대신 품질 −10, 질문과 낱말이 겹치지 않는 정답 문장을 버림)과 같은 방향입니다 — 빨라지는 것은 확실하고 품질 손실은 이번 표본으로는 확인도 부정도 못 합니다.
- 한계: 질문마다 한 팔만 답하므로(서비스와 같은 방식) 질문 난이도 차이가 팔 차이에 섞입니다. 같은 질문을 두 설정으로 답해 짝지어 보는 것은 2 RAG 의 답변 평가 · 연결 비교가 맡습니다.
