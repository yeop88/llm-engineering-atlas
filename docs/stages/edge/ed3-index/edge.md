# 온디바이스 · 엣지 — 기기 추천 · 경량화 조합 · 기기용 팩 · 오프라인 · 동기화 · 개인정보 · 실측 (ED1~ED6)

화면은 `/edge/select`(기기별 모델 · 경량화) · `/edge/pack`(기기용 팩 · 오프라인) · `/edge/sync`(기기 동기화 · 개인정보), 코드는 `app/stages/edge/` 입니다. 기기 쪽 동작(팩 검색 · 캐시 · 대기열 · 올리기 전 마스킹)은 서버가 팩 폴더를 기기와 똑같이 읽어 흉내 냅니다 — 실제 기기 앱 없이 오프라인 품질 · 동기화 크기 · 새는 개인정보를 재려는 것입니다.

```
기기 프로필(앱 메모리 예산 · 저장 공간 · 가속기) ─ 실측(벡터 양자화 · LLM 양자화) → 예산 안 조합 · 파레토 (ED1 · ED2)
   ↓ 담당 범위(제품 모델 · 문서 종류 · 최근)의 청크 → 압축 벡터 팩 v1, v2 … (바뀌지 않은 문서는 벡터 재사용) (ED3)
   ↓ 기기: 자주 묻는 답 → 팩 검색 → 기기 LLM / 근거만 — 서버가 필요한 일은 대기열 (ED4)
   ↓ 연결: 판 증분(문서 지문 비교, 적용 결과 지문 확인) · 기기 버전 표시 (ED5)
   └ 올리기: 항목별 전송 정책(기기) → 서버 재검사 → 가린 값만 저장 · 위반 기기 표시 → 미룬 요청은 서비스 답변으로 (ED6 · ED4)
```

## 설계

- **추천은 이미 잰 실측에서.** 기기마다 새로 잴 수 없어, 벡터 양자화 비교(`quant_vectors`: 가중치 × 차원 × 정밀도별 recall@10 · 벡터 바이트)와 LLM 양자화 비교(`quant_llm`: 품질 · 지연), GGUF 파일 크기를 모읍니다. 메모리는 추정입니다 — 임베딩 = 파라미터 × 가중치 바이트, 색인 = 청크 수 × 벡터 바이트, LLM = 파일 크기 + 맥락 1K 당 0.06GB(KV). 앱이 쓸 수 있는 예산은 전체 RAM 보다 훨씬 작게 잡았습니다(OS · 다른 앱 몫).
- **조합 점수 = recall × 품질.** 압축은 따로 쟀지만 겹치면 손실이 누적되므로(양자화 실측), 두 손실이 함께 깎이는 곱으로 점수를 매기고 같은 메모리에서 더 나은 조합이 없는 것만 파레토 앞줄로 둡니다. 품질을 재지 않은 LLM 은 추측하지 않고 '미측정'으로 남깁니다. LLM 없이 근거만 보여 주는 조합도 후보입니다.
- **팩 = 폴더 하나.** `manifest.json`(모델 · 정밀도 · 문서별 sha256 · 청크 번호 · 지문) + `chunks.jsonl` + `vectors.npz` + `cache.jsonl`. 기기에는 벡터 DB 가 없고, 작은 색인은 전부 훑는 정확 검색이 가장 단순하며 근사 검색의 재현율 손실도 없습니다. 압축은 기기에 담기는 모양 그대로 — int8 · int4 는 차원별 범위로 고른 정수(int4 는 한 바이트에 둘), binary 는 부호 비트 + 재점수용 int8. 질의는 float 로 두고 문서만 복원합니다(비대칭, 질의까지 줄이면 손실이 컸음).
- **판을 이어 만든다.** 새 판을 만들 때 바뀌지 않은 문서(sha256 같음 · 같은 모델 · 정밀도 · 청크 세트)의 벡터는 앞 판에서 가져오고 첫 판의 눈금(lo · hi)을 이어 씁니다. 서버도 바뀐 청크만 인코딩해야 증분 동기화로 보낸 값과 같아집니다.
- **범위 밖을 따로 센다.** 팩 평가는 같은 질문을 서버 전체 검색으로도 돌리고, 정답 문서가 팩 범위 밖인 질문을 따로 셉니다 — 범위 안에서의 차이는 압축 손실, 전체와 범위 안의 차이는 '안 담아서 못 찾은' 몫입니다. 무엇을 담을지가 압축만큼 중요하다는 것을 수치로 보려는 것입니다.
- **오프라인은 거절이 아니라 미룸.** 자주 묻는 답(근거가 모두 팩 안 · 같은 모델 벡터) → 팩 검색 → 기기 LLM(없으면 근거만). 법령 최신 조회 · 그래프 집계 · 팩 안에서 근거를 못 찾은 질문은 미룬 요청으로 대기열에 넣고 사용자에게 이유와 '연결되면'을 보입니다. 질문 분류는 규칙입니다 — 기기에서 LLM 판정을 부를 여유가 없습니다.
- **증분은 계산으로 확인.** 두 판의 문서 지문을 비교해 바뀐 · 새 문서의 청크만 보내고, 바뀐 문서의 옛 청크는 모두 지웁니다(한 문서 안에 옛 · 새 청크가 섞이지 않게). 기기가 적용한 결과의 지문(문서 지문 + 청크 번호 + 모델 + 정밀도)이 서버 최신 판 지문과 같은지 서버가 미리 맞춰 봅니다. 모델 · 정밀도 · 청크 세트가 바뀌면 벡터 공간이나 눈금이 달라 전체를 다시 보냅니다.
- **기기 버전 관리.** 기기마다 받은 팩 · 판 · 마지막 동기화를 남겨 판이 뒤처진 기기 · `EDGE_STALE_HOURS`(기본 72) 넘게 연결 안 된 기기를 표시합니다 — 같은 질문에 기기마다 다른 답이 나오는 원인입니다.
- **개인정보는 기기에서 걸러 보내고 서버가 다시 본다.** 항목별 정책: 질문 · 답 · 피드백은 가림, 평점 · 진단 결과는 원문, 사용 기록은 집계만, 고객 정보 · 사진 원본은 보내지 않음. 서버는 받은 값을 G2 탐지로 다시 검사해, 새어 들어온 개인정보나 정책상 오면 안 되는 항목이 있으면 원문을 저장하지 않고 가린 값만 남기며 위반을 기록합니다(기기 앱 판 · 탐지 규칙이 서버보다 늦을 수 있어 기기 마스킹을 믿지 않음). 기기 목록에 위반 수가 보입니다.
