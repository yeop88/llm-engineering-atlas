# 추론 모델 — 생각 예산 · 라우팅 · 여러 번 풀기 · 검증기 · 생각 검사 · 추론 증류 · 실측 (RS1~RS6)

화면은 `/reasoning/budget`(생각 예산 · 라우팅) · `/reasoning/sampling`(여러 번 풀기 · 검증기) · `/reasoning/trace`(생각 과정 검사 · 추론 증류), 코드는 `app/stages/reasoning/` 입니다. 과제는 RLVR 의 검증 가능한 과제를, 관찰(검색 근거 · 그래프 집계)은 RLVR 의 기록 재생 환경을 그대로 씁니다.

```
RLVR 과제(조문 제목 · 번호 · 인용 수 · 계산) + 기록 재생 관찰
   ↓ 풀기: 생각 켬 + max_tokens = 예산 + 답 몫 → 예산을 넘으면 잘린 생각으로 답만(예산 강제)
   ↓ 풀이 저장소(과제 묶음 × 모델 × 예산 × 온도) — 아래 모든 실험이 같은 풀이를 다시 씀
   ├ 예산 곡선: 예산별 정답률 · 생각 토큰 · 시간 · 유형별 꺾이는 점 (RS1)
   ├ 라우팅: 끔 · 켬 풀이로 늘 끔 · 늘 켬 · 라우터 · 이상적 (RS2)
   ├ 여러 번 풀기: n = 1 … N 다수결 · 검증기 고르기 · pass@n (RS3)
   ├ 검증기: 형식 · 근거에 있음 · 과정 채점 · LLM 판정의 AUROC (RS4)
   ├ 생각 검사: 생각-답 불일치 · 근거 밖 주장 · 개인정보 · 지시 따르기 (RS5)
   └ 증류: 맞은 풀이 → SFT 데이터 → 후학습(LoRA) → RLVR 평가 (RS6)
```

## 설계

- **정답을 자동으로 확인할 수 있는 과제로.** 생각 예산 · 표본 수 · 검증기의 효과는 정답률 차이로만 보입니다. LLM 판정으로 채점하면 판정의 오류가 효과를 덮습니다. 그래서 RLVR 과제(조문 제목 · 번호 — 법령 정형 추출, 인용 수 — 그래프 집계, 계산 — 두 수의 합)를 그대로 쓰고, 정답 확인도 RLVR 의 규칙(마지막 '정답:' 줄 · 정규화)을 씁니다.
- **예산 강제.** llama-server 등 OpenAI 호환 서버는 요청마다 생각 예산을 받지 않습니다. 생각을 켜고 max_tokens = 예산 + 답 몫(200)으로 부르고, 생각이 예산을 다 써 답을 못 냈으면 잘린 생각(끝 3,000자 — 결론에 가까운 쪽)을 붙여 생각을 끈 채 '지금까지의 생각으로 답하라'고 한 번 더 부릅니다. 어느 서버에서나 같은 상한이 걸리고, 강제된 비율도 함께 남깁니다. Claude API 는 확장 생각 예산(1024 이상)을 그대로 씁니다. 공용 LLM 호출(`llm.chat`)에 `thinking` · `thinking_budget` 인자와 생각 글(`reasoning`) 돌려주기를 더했고, 인자를 주지 않으면 이전 동작(설정 LLM_DISABLE_THINKING) 그대로입니다.
- **생각 토큰은 추정.** 서버가 생각 · 답 토큰을 나눠 주지 않아, 출력 토큰을 생각 · 답 글자 비율로 나눕니다. 곡선의 가로축은 설정한 예산이고, 생각 토큰은 실제로 얼마나 썼는지 참고용입니다.
- **풀이 저장소.** 과제 묶음 · 모델 · 예산 · 온도마다 파일 하나(`data/reasoning/banks/`)에 풀이를 이어 씁니다. 모자란 만큼만 새로 풀고, 중간에 멈춰도 남습니다. 예산 곡선 · 라우팅 · 여러 번 풀기 · 검증기 · 생각 검사 · 증류가 같은 풀이를 다시 써서 — 이 PC 생성이 초당 13 토큰이라 같은 풀이를 다시 만들지 않으려는 것이고, 같은 풀이로 비교해야 검증기 · 라우터의 차이가 생성의 우연이 아니라 방법의 차이가 됩니다.
- **꺾이는 점은 유형별로.** 최고 정답률에서 허용 폭(기본 2%p) 안에 드는 가장 작은 예산입니다. 조회(제목 · 번호)는 생각이 필요 없고 계산 · 집계만 생각이 필요할 수 있어, 전체 꺾이는 점 하나로 정하면 쉬운 질문까지 비싸집니다 — 그래서 라우팅(RS2)과 이어집니다.
- **라우터는 질문 글만 본다.** 과제의 유형 · 난이도 표시를 보면 시험이 아닙니다. 규칙 라우터는 계산 · 집계 · 결합 표현(합치면 · 몇 건 · 각각)을 찾고, LLM 라우터는 생각 없이 한 낱말(어려움/쉬움)만 묻습니다 — 라우터가 비싸면 이득이 사라지므로 라우터 토큰도 비용에 넣습니다. '이상적'은 끔으로 맞히면 끄고 켬으로만 맞히면 켜는 정책으로, 라우터가 얻을 수 있는 상한입니다.
- **곡선은 한 번에.** 여러 번 풀기는 n 개 풀이를 쌓은 뒤 앞 n 개만 써서 n = 1 … N 의 정답률을 계산합니다(새로 부르지 않음). pass@n(하나라도 맞음)은 고르기 방법의 상한이라, 다수결 · 검증기 고르기가 pass@n 에서 멀수록 고르는 방법이 병목입니다.
- **검증기는 정답을 모른다.** 정답을 알면 검증기가 필요 없습니다. 형식('정답:' 줄)은 가장 약한 기준선, '근거에 있음'은 답이 자료 · 그래프 집계(또는 두 집계의 합)에 그대로 있는지, '과정 채점'은 생각의 문장마다 나온 조문 번호 · 수가 자료 · 질문 · 집계에서 왔는지의 평균(과정 보상의 규칙판), LLM 판정은 생각 없이 0~1 점. 검증기 자체의 정확도는 맞은 · 틀린 풀이를 가르는 AUROC 로 봅니다 — LLM 판정은 그 자체가 틀리므로(검증 보정 실측) 따로 재야 합니다.
- **생각 글도 출력이다.** 생각의 마지막 결론(끝 300자의 마지막 조문 번호 · 수)과 최종 답이 다르면 답을 믿기 어렵고, 생각에만 나온 조문 번호 · 수는 근거 밖 주장입니다. 생각을 기록하거나 보여 주면 개인정보 · 받아 적은 숨은 지시도 그대로 나갑니다. 표시마다 표시된 풀이와 나머지의 정답률을 함께 내, 그 검사가 쓸모 있는 신호인지(표시된 풀이가 실제로 더 틀리는지) 확인합니다.
- **증류는 맞고 짧은 풀이로, 학습 과제에서만.** 과제마다 맞은 풀이 중 예산 강제가 없고(선택: 검사 표시 없음) 생각이 가장 짧은 것 하나를 고릅니다 — 긴 풀이를 배우면 작은 모델도 길게 생각합니다. 시험 과제는 학습한 모델을 평가할 때 남겨 둡니다(누수 방지). 생각 포함(풀이 증류) · 답만(답 증류)을 같은 과제로 비교할 수 있게 둘 다 만들 수 있고, 학습은 후학습(LoRA SFT), 평가는 RLVR 평가(`pt-<번호>`)가 맡습니다.
