# 에이전트 — 방법 · 실측

LLM 이 도구를 여러 번 써서 답하는 다단계 RAG 입니다(ReAct: 생각 → 행동 → 관찰 반복). 화면은 `/agent`(에이전트 테스트)이고, 연결 실행 · 라우팅에서 '답변 방식 = 8a 에이전트'로 일반 RAG 와 같은 질문으로 비교합니다.

## 도구

| 도구 | 하는 일 | 왜 |
|---|---|---|
| search | 다른 표현 · 하위 질문으로 다시 검색 | 한 번의 검색으로 근거가 다 안 나올 때 |
| read | 찾은 지문의 앞뒤 청크 읽기 | 표 · 조문이 청크 경계에서 잘렸을 때 |
| calc | 산술식 계산(파이썬 eval 을 쓰지 않는 안전한 계산기) | 금액 · 날짜 계산 |
| lookup (선택) | 법령 조문 · 판례를 번호로 바로 찾기 (`근로기준법 제23조`, `2019다12345`) | 번호로 묻는 법률 질문은 임베딩 · BM25 가 제23조와 제24조를 잘 구분하지 못함 |
| finish | 모은 근거를 번호로 인용해 답하기 | — |

**법률 번호 조회**(`agent.lookup=true`, 화면의 '법률 번호 조회'): 문서 이름 규칙은 공개 자료 가져오기와 같습니다 — 법령은 `<법령명>.txt`(본문에 `제N조(제목)` 줄), 판례는 `판례 <사건번호> <사건명>.txt`. 조문은 조문 머리(`제23조(` 로 시작하는 줄)만 찾아, 본문 속 '제23조에 따른' 같은 언급은 뺍니다. 켜면 답변에 나온 번호도 검사합니다(아래 '번호 검사').

**번호 검사**(`rag/legal.py` `check_citations`): 답변에서 조문 · 사건번호를 뽑아 ① 인용한 근거 글에 있으면 `근거에 있음`, ② 근거에는 없고 컬렉션에는 있으면 `근거 밖 · 자료에 있음`(근거 밖 지식으로 답함 — 확인 필요), ③ 어디에도 없으면 `자료에 없음`(지어낸 번호일 가능성이 큼). 문장별 근거 검증(글자 · 의미)은 '제23조'를 '제32조'로 바꾼 문장을 거의 못 잡으므로(나머지 글이 같음) 따로 둡니다. 답변 생성 · 연결 실행에서도 답변에 번호가 나오면 자동으로 검사합니다(정규식 + DB 조회라 거의 비용 없음).

설계에서 고른 것과 이유:

- **행동은 JSON 한 객체**(`{"thought", "action", "input"}`). 작은 로컬 LLM 은 제공자별 함수 호출 지원이 고르지 않고, JSON 은 이미 평가 질문 생성 등에서 안정적으로 쓰고 있습니다. 형식 오류가 두 번이면, 또는 단계 상한(기본 5)에 닿으면 모은 근거로 RAG 처럼 한 번에 답합니다(빈손으로 끝나지 않게).
- **도구는 셋으로 작게.** 도구가 많을수록 작은 모델이 잘못 고릅니다.
- 모은 지문은 모두 번호로 모으고, 최종 답은 RAG 답변과 같은 **문장별 근거 검증**을 거칩니다 — 그래서 일반 RAG 와 같은 지표로 비교할 수 있습니다.
- 연결 실행에서는 이미 한 첫 검색을 에이전트에 넘겨 같은 검색을 반복하지 않습니다.
- 단계마다 생각 · 행동 · 관찰 · 시간을 기록(화면에 실시간 스트리밍)합니다. 에이전트의 비용은 단계 수에 비례합니다.

## 실측

### #1 · 2026-10-18 · 일반 RAG vs 에이전트 vs Best-of-4 (연결 비교, run #233)

- 공공문서 · 직접 작성 24문항 중 10문항, KURE-v1 의미 검색, Gemma 4 E4B(QAT Q4_0). 에이전트: 최대 5단계, 검색당 지문 4개.

| 답변 방식 | 정답 근거 인용 | 문장 근거율 | 답변률 | 질문당 지연 |
|---|---|---|---|---|
| 일반 RAG | 90 | 76.7 | 100 | 6.0초* |
| 8a 에이전트 | 90 | **38.3** | 100 | 63.8초 (p95 134초) |
| 8b Best-of-4 | 90 | 80.0 | 100 | 20.9초* |

\* 일반 RAG · Best-of-N 은 앞선 실측이 같은 질문 · 근거를 처리해 둔 llama-server 프롬프트 캐시를 재사용해 지연이 짧게 잡혔습니다(품질에는 영향 없음). 캐시 없이 재면 일반 RAG 는 질문당 약 30초입니다(양자화 실측 #1). 이 실측 뒤 연결 비교도 캐시를 끄도록 고쳤습니다.

읽은 것

- **이 질문들에는 에이전트가 필요 없었습니다.** 정답 근거 인용은 같고(90%), 에이전트는 문장 근거율이 절반으로 떨어졌으며 지연은 10배 이상입니다.
- 근거율이 떨어진 이유: 에이전트의 최종 답은 여러 단계에서 모은 지문을 요약하며 말을 바꿔 써, 인용한 지문과 글자 겹침이 줄어듭니다(이 앱의 문장 검증은 글자 기반). 일반 RAG 는 근거 5개를 한 번에 보고 그대로 옮겨 적는 경향이 있습니다.
- 사실 확인형 질문이 대부분인 자료라 한 번 검색으로 충분했습니다. 에이전트의 효과는 여러 문서를 엮어야 하는 질문 · 청크 경계에서 잘린 표에서 재야 하고, 라우팅으로 그런 질문에만 쓰는 것이 맞습니다.
