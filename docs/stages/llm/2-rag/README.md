# 2 · RAG 검색 (Retrieval-Augmented Generation)

**상태: ✅ 구현됨** — 내 문서에서 근거를 찾아 LLM 이 그 근거로 답하게 한다

## 원리

문서를 조각(청크)으로 나눠 임베딩해 색인하고, 질문도 같은 공간에 놓아 가까운 청크를 찾습니다(의미 검색). 형태소 기반 키워드 검색(BM25)과 합치면(하이브리드) 고유명사 · 숫자에도 강해집니다. 찾은 청크에 번호를 붙여 LLM 에 넘기고, LLM 은 그 근거만으로 답하며 번호를 인용합니다.

## 왜 하는가

LLM 은 사내 문서 · 최신 정보를 모르고, 모르면 그럴듯하게 지어냅니다(환각). 검색한 근거로 답하게 하면 정확해지고 출처를 댈 수 있습니다. 청킹 · 모델 · 검색 방식 조합에 따라 품질이 크게 달라 숫자로 비교해야 합니다.

## 어떻게 (이 앱에서)

- 컬렉션에 문서 업로드(HWP · PDF · DOCX …) 또는 공개 자료 가져오기(법령 · 판례) → 청킹 전략 → 벡터 인덱스(모델 · 저장소)
- 검색 비교, 평가 세트(LLM 질문 7유형 — 조건 · 긴 상황 · 여러 문서 · 답 없음 포함, 직접 입력)와 조합 평가(신뢰구간 · 짝지은 비교)
- 답변 생성: 질문에 대한 답 + 관련된 부가 설명만, 근거 번호 인용 · 문장별 근거 일치와 질문 관련성 검증 · 평가 세트로 답변 일괄 평가

## 화면

- `/collections` — **컬렉션**: 문서 · 청킹 · 인덱스 · 검색 비교 · 평가
- `/rag/answer` — **답변 생성**: 근거 인용 답변 · 환각 검증
- `/rag/verify` — **검증 보정**: 사람 판정(근거 일치 · 질문 관련성)으로 검증 방식과 기준 고르기
- `/llm` — **LLM 연결**: 로컬 · OpenAI 호환 · Claude

## 앞으로 할 일

- 비슷한 문서가 많은 자료(판례)에서 답 없는 질문 거절 개선 — 법률 재측정에서 13개 중 1개만 거절
- 여러 문서 질문을 늘린 평가 세트(관련 지문 쌍이 적어 9문항뿐)
