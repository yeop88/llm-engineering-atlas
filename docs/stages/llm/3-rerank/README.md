# 3 · 리랭킹 (Re-ranking)

**상태: ✅ 구현됨** — 1단계 검색이 고른 후보를 정밀하게 다시 줄 세운다

## 원리

1단계 검색(벡터 · BM25)이 고른 후보 수십 개를, 질문과 문서를 한 번에 읽는 크로스 인코더 또는 LLM 으로 다시 점수 매겨 줄 세웁니다. 후보마다 모델을 돌리므로 정확하지만 느립니다.

## 왜 하는가

벡터 검색은 빠르지만 거칩니다. RAG 는 상위 몇 개만 LLM 에 넣기 때문에 1~3위의 정확도가 답변 품질을 좌우합니다. 다만 리랭커가 1단계의 정답을 끌어내리는 경우도 있어(실측) 반드시 재고 씁니다.

## 어떻게 (이 앱에서)

- 크로스 인코더 리랭커(11종) · LLM 목록형 리랭커(후보를 한 번에 보여 주고 순서를 받음 — 호출 1번)
- 리랭크 융합: 리랭커 순위와 1단계 순위를 RRF 로 합쳐 한쪽의 실수를 다른 쪽이 메움
- 평가: 리랭커 × 후보 수 × 융합의 품질-지연 — 크로스 인코더 점수는 가장 큰 후보 수에서 한 번만 매기고 잘라 계산

## 화면

- `/rerank` — **리랭킹 테스트**: 리랭커 · 후보 수 · 융합 · LLM 리랭커 비교

## 앞으로 할 일

- 질문 유형별로 리랭킹을 켜고 끄는 라우팅
