# 3 · 리랭킹 (Re-ranking)

**상태: 🟡 기초 있음** — 1단계 검색이 고른 후보를 정밀하게 다시 줄 세운다

## 원리

1단계 검색(벡터 · BM25)이 고른 후보 수십 개를, 질문과 문서를 한 번에 읽는 크로스 인코더(또는 LLM)로 다시 점수 매겨 줄 세웁니다. 후보마다 모델을 돌리므로 정확하지만 느립니다.

## 왜 하는가

벡터 검색은 빠르지만 거칩니다. RAG 는 상위 몇 개만 LLM 에 넣기 때문에 1~3위의 정확도가 답변 품질을 좌우합니다.

## 어떻게 (이 앱에서)

- 지금: 검색 비교 · 조합 평가 · 답변 생성에서 리랭커 11종 선택 (재정렬 후보 수 조절)
- 실측: CPU 에서 후보 10개 재정렬에 질문당 약 22초 — GPU · 양자화가 필요

## 화면

- 아직 테스트 화면이 없습니다. 단계 소개는 앱의 `/stages/rerank` 에서 볼 수 있습니다.

## 앞으로 할 일

- 리랭커 전용 벤치마크와 후보 수(top-k) · 지연 곡선
- LLM 리랭커(목록형 재정렬)와 크로스 인코더 비교
- 양자화 · ONNX 로 속도 개선 후 재측정
