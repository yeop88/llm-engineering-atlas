# 지식 증류 — 방법 · 실측

큰 모델(교사)의 판단을 작은 모델(학생)이 따라 하게 학습합니다. 화면은 `/distill`(지식 증류 테스트)입니다.

## 임베딩 증류 (MarginMSE)

```
컬렉션 지문 → 학습 질문(LLM · ICT, 평가 세트 근거 지문 제외)
          → 교사: 질문마다 오답 고르기 + 점수 차(정답 − 오답)
          → 학생 학습: 학생의 점수 차가 교사의 점수 차를 따라가게 (MarginMSELoss)
          → 카탈로그 등록 → 교사 · 학생(전) · 학생(후) 같은 평가 세트로 비교 + 인코딩 속도
```

- **점수 '차이'를 배우는 이유**: 교사와 학생의 벡터 차원이 달라도 되고, 교사가 리랭커(크로스 인코더)여도 됩니다. 벡터 자체를 따라 하게(MSE) 하려면 차원이 같아야 합니다.
- **오답 고르기**: 교사가 임베딩 모델이면 교사가 질문과 가장 가깝다고 본 *다른 문서의* 지문(어려운 오답 — 쉬운 오답은 배울 것이 적음, 같은 문서의 지문은 실제로 답을 담고 있을 수 있어 제외). 교사가 리랭커면 모든 후보를 매기기엔 너무 느려 다른 문서에서 무작위로 고릅니다.
- **교사가 오답을 더 높게 본 비율**(`teacher_disagrees`)을 기록합니다 — 높으면 질문 생성이 나쁘거나 오답이 실제로 답을 담고 있을 수 있습니다.
- 파인튜닝(5)의 학습 데이터 · 학습기 · 카탈로그 등록 · 실행 기록을 그대로 쓰고 정답 신호만 다릅니다. 실행 기록은 파인튜닝 화면에도 함께 보입니다.
- **격차 회복률** = (학습 후 − 학습 전) ÷ (교사 − 학습 전). 학생이 교사와의 차이를 얼마나 줄였는지.

## LLM 증류 데이터

작은 LLM 을 CPU 에서 직접 학습시키는 것은 현실적이지 않아, 이 앱은 **좋은 학습 데이터**까지 만들고 학습(SFT)은 GPU 환경의 TRL · Unsloth · LLaMA-Factory 등에 맡깁니다.

- 컬렉션 지문에서 **새 질문**을 만듭니다(평가 세트는 쓰지 않음 — 나중에 그 세트로 학생을 재야 하므로). 평가 세트 근거가 든 지문은 뺍니다.
- 교사 LLM 이 서비스와 **똑같은 형식**(시스템 지시 + 근거 번호 + 질문)으로 답하게 합니다 — 학생이 '근거를 인용하며 답하기'라는 행동을 배우도록.
- 거절 · 잘못된 인용 · 문장 근거율 미달 답은 버립니다(교사의 환각 버릇까지 배우지 않게).
- 형식: OpenAI 대화 형식 JSONL (`{"messages": [system, user, assistant]}`), `data/distill/` 에 저장, 화면에서 내려받기.
