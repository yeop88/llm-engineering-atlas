# 컨텍스트 엔지니어링 — 배치 · 바늘 위치 · 긴 맥락 vs RAG · 압축 · 캐시 · 노트 · 오염 방지 · 실측 (CX1~CX6)

화면은 `/context/layout`(맥락 배치 · 긴 맥락 · 캐시) · `/context/compact`(기록 압축 · 노트) · `/context/hygiene`(맥락 오염 방지), 코드는 `app/stages/context/` 입니다.

```
평가 세트(근거 문장이 있는 · 답할 수 있는 질문) + 컬렉션 서비스 기본 검색
   ↓ 맥락만 바꾼다 — 채점은 모두 같은 evaluate_one(정답 근거를 인용했나)
   ├ 배치: 관련도 순 · 역순 · 샌드위치, 정답 근거 위치별 (CX1)
   ├ 긴 맥락: 검색 근거 vs 정답 문서 통째 + 다른 문서(4K · 12K · 24K 자) (CX2)
   ├ 압축: 하위 질문 기록 뒤 처음 단계 사실 묻기 — 그대로 · 지움 · 요약 · 노트 (CX3)
   ├ 캐시: 근거 앞 vs 질문 앞 — 다시 읽은 토큰 (CX4)
   ├ 노트: 세션 노트 쓰기 · 질문과 겹치는 노트 읽기 (CX5)
   └ 오염: 틀린 이전 결과 → 그대로 · 표시 · 빼기 · 원문 먼저 (CX6)
```

## 설계

- **맥락만 바꾸고 채점은 같게.** 모든 실험이 같은 질문 · 같은 모델 · 같은 채점(`rag.answer.evaluate_one`: 정답 근거를 인용했나)을 씁니다. 근거 문장이 있고 답할 수 있는 질문만 씁니다 — 답 없는 질문(거절해야 정답)은 맥락 설계와 다른 물음이라 섞으면 효과가 흐려집니다. 질문마다 LLM 을 한 번 부르고, 서버 캐시는 끕니다(`no_cache`, 캐시 실험만 예외) — 앞 실행의 캐시가 순서 비교를 무너뜨리지 않게(양자화 실측에서 겪은 문제).
- **배치(CX1).** 같은 근거 k 개를 관련도 순(1위가 맨 앞) · 역순(1위가 질문 바로 앞) · 샌드위치(1 · 3 · 5위는 앞, 2 · 4위는 뒤)로 넣습니다. 바늘 위치는 정답 근거를 담은 청크 하나와 근거가 없는 청크 k-1 개(같은 검색의 아래 순위)로, 정답 위치만 바꿔 정답률을 잽니다. 정답 근거가 검색되지 않았거나 방해 근거가 모자란 질문은 뺍니다.
- **긴 맥락 vs RAG(CX2).** 정답 문서 통째와 다른 문서들을 글자 한도까지 붙이고, 정답 문서 위치는 임의로 둡니다 — 늘 앞에 두면 긴 맥락에 유리하게 기웁니다. 한도가 작으면 정답 문서가 잘려 빠질 수 있어 '정답 문서가 들어갔나'를 함께 셉니다. 검색 근거는 서비스 기본 검색 top-k(기본 6개 · 6,000자). 이 PC 에서 읽기 시간이 지연의 2/3 였으므로 입력 토큰 · 시간이 정답률만큼 중요한 결과입니다.
- **압축(CX3).** 긴 작업을 흉내 낸 기록: 같은 세트의 다른 질문들을 하위 질문으로 검색한 결과(단계당 3개)가 쌓이고, 정답 단계(이 질문의 검색 결과)를 앞에서 `gold_at` 번째에 넣은 뒤 마지막에 이 질문을 묻습니다. 최근 `keep` 단계는 그대로 두고 그보다 오래된 단계를 방법별로 줄입니다 — 그대로(한도를 넘으면 뒤가 잘림) · 지움 · LLM 요약(2문장, 요약 호출 시간도 셈) · 노트(단계 질문과 가장 겹치는 문장 2개, LLM 없음). 정답 단계가 앞에 있어 압축 방법이 오래된 결과를 어떻게 다루는지가 그대로 정답률에 나타납니다.
- **캐시(CX4).** llama-server 는 앞 요청과 같은 앞부분의 계산(KV)을 다시 씁니다. 같은 근거로 질문을 연달아 할 때 근거를 앞 · 질문을 끝에 두면 두 번째 질문부터 근거를 다시 읽지 않고, 질문을 앞에 두면 매번 처음부터 읽습니다. 서버가 돌려주는 단계별 시간(다시 읽은 토큰 `prompt_n` · 읽기 시간)으로 재사용 비율을 셉니다 — 다른 서버는 이 값이 없어 비어 있습니다. 서버의 병렬 슬롯(`-np`)이 여럿이면 요청이 다른 슬롯에 가 재사용이 낮게 나올 수 있습니다.
- **노트(CX5).** 맥락을 압축하면 잃는 것이 생기므로, 에이전트가 세션 노트(출처 · 시각과 함께)에 적고 질문과 겹치는 노트만 다시 읽습니다. 노트를 모두 맥락에 넣으면 노트를 둔 의미가 없습니다. 쓰기 규칙은 압축 시험의 '노트만'과 같아, 압축 시험이 곧 노트 방식의 시험입니다. 출처 · 시각은 낡은 노트를 가려내고 오염을 막는 데(CX6) 씁니다.
- **오염(CX6).** 정답 근거의 첫 수를 바꾼 문장을 '이전 단계 결과'로 넣고(에이전트가 앞 단계에서 잘못 읽은 값을 적어 둔 상황), 답에 바뀐 수가 나오면 오염입니다. 막는 방법: 그대로 섞기(1위 근거 바로 뒤 — 그럴듯한 자리) · 출처와 '검증 실패' 표시 · 검증 실패 결과 빼기(판정을 맥락 관리가 따름 — 기준선) · 원문 근거를 앞에 두고 이전 결과는 맨 뒤 '참고'로. 표시만으로 막히는지, 빼야만 막히는지를 봅니다.
