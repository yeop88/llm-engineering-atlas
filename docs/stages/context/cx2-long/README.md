# CX2 · 긴 맥락 vs RAG (Long context vs retrieval)

**상태: ✅ 구현됨** — 문서를 통째로 넣는 것과 검색 근거를 넣는 것을 같은 질문으로 비교한다

## 원리

긴 맥락은 검색 없이 문서 전체를 넣고, RAG 는 관련 부분만 찾아 넣습니다. 문서가 작으면 긴 맥락이, 크거나 많으면 RAG 가 유리합니다.

## 왜 하는가

긴 맥락 모델이 나왔으니 RAG 가 필요 없다는 주장이 있습니다. 이 자료 · 이 하드웨어에서 정답률 · 비용 · 지연으로 갈림 지점을 재야 합니다.

## 어떻게 (이 앱에서)

- (기반) RAG 검색 · 평가(2)
- 같은 질문에 검색 근거 top-k vs 정답 문서 통째 + 다른 문서를 글자 한도(4K · 12K · 24K …)까지 — 정답 문서 위치는 임의
- 정답률 · 입력 토큰 · 시간과 '정답 문서가 한도 안에 들어갔나'
