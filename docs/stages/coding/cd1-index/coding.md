# 코딩 에이전트 — 코드 검색 · 깬 코드 과제 · 계획 · 패치 · 테스트 주도 고치기 · 리뷰 · 해결률 · 실측 (CD1~CD6)

화면은 `/coding/search`(코드 검색) · `/coding/agent`(코딩 에이전트) · `/coding/review`(코드 리뷰), 코드는 `app/stages/coding/` 입니다.

```
저장소 복사본(app · tests · migrations · 설정) — 원본 · 실행 중인 서버는 건드리지 않음
   ├ 색인: ast 로 함수 · 클래스 단위 · 호출 이름 → BM25(식별자 쪼개기) + 기호 일치 + 호출 그래프 (CD1)
   ├ 깬 코드 과제: 테스트가 가져오는 모듈에 돌연변이 → 테스트가 실패하는 것만 (CD6)
   ↓ 과제마다 새 작업 공간 + 돌연변이
   ↓ 계획: 실패 출력 + 검색 상위 → 고칠 파일 · 함수 후보 (CD2)
   ↓ 걸음마다 도구 하나: 찾기 · 읽기 · 정확한 교체 (CD3) → 바로 테스트 → 실패 출력을 다음 걸음에 (CD4)
   ↓ 끝: 테스트 · diff · 테스트 파일을 건드렸나
   └ 리뷰: 비밀 값 · 위험 함수 · 테스트 약화 · 의존 방향 · 예외 삼키기 (+ LLM) (CD5) → 해결률 · 걸음 · 토큰
```

## 설계

- **과제는 이 저장소에서 만든다.** 공개 벤치마크(SWE-bench 등)는 학습 데이터에 섞였을 수 있습니다. 테스트가 가져오는 모듈의 함수에 한 줄짜리 돌연변이(비교 연산자 뒤집기 · and/or 바꾸기 · 작은 정수 +1)를 넣고, 그 테스트 파일이 실제로 실패하는 것만 과제로 둡니다. 정답(원래 줄)이 정해져 있고, 이슈는 '실패한 테스트 출력'입니다. 테스트가 잡지 못하고 살아남은 돌연변이 수도 함께 남겨 — 그것은 테스트의 빈틈입니다(돌연변이 시험). 대상 테스트는 모델을 올리지 않는 빠른 파일들(통계 · 음성 규칙 · 엣지 로직)을 기본으로 합니다. 설정 · DB 모델 파일은 값 모음이라 돌연변이가 잡히지 않아 뺍니다.
- **작업 공간.** 저장소의 app · tests · migrations · scripts · 설정을 복사한 원본(`data/coding/base`)을 한 번 만들고, 과제마다 그것을 다시 복사해 돌연변이를 넣습니다. 테스트는 같은 파이썬으로 작업 공간에서(PYTHONPATH = 작업 공간) 돌려 원본 · 실행 중인 서버를 건드리지 않습니다. 저장소를 고친 뒤에는 '복사본 새로'로 원본을 다시 만듭니다(이미 만든 과제의 줄 번호가 달라질 수 있음).
- **코드 검색은 기호가 먼저.** 코드는 함수 하나가 뜻의 단위이고, 이슈에는 함수 이름 · 파일 경로 · 오류 줄이 그대로 나옵니다. 함수 · 클래스(메서드) 단위로 나누고, BM25 낱말은 식별자를 snake_case · CamelCase 로 쪼갭니다. 질문에 나온 이름 · 파일 경로에 크게 더하고(기호 일치), 실패한 테스트가 부른 함수와 상위 함수가 부르는 함수를 이웃으로 더합니다(호출 그래프). 세 방법을 깬 코드 과제로 비교합니다 — 정답은 돌연변이를 넣은 함수입니다.
- **한 걸음에 도구 하나.** 계획(고칠 파일 · 함수 후보 · 이유)을 첫 맥락에 넣고, 걸음마다 찾기 · 읽기(줄 범위) · 교체 · 테스트 · 끝 중 하나를 JSON 으로 고르게 합니다. 교체는 파일에 정확히 한 번 있는 글만 — 파일 전체를 다시 쓰면 고치지 않은 곳이 바뀌거나 사라지고 리뷰 · 되돌리기도 어렵습니다. 문법이 깨진 교체는 곧바로 되돌립니다(다음 걸음이 깨진 파일 위에 쌓이지 않게).
- **고칠 때마다 테스트.** 교체가 성공하면 그 과제의 테스트를 바로 돌려 결과를 다음 걸음에 줍니다 — 실패 출력이 가장 정확한 피드백입니다. 테스트 파일은 고칠 수 없게 막고, 끝난 뒤 diff 가 테스트를 건드렸으면 통과해도 '해결'로 세지 않습니다 — 테스트를 고쳐 통과시키는 것은 해결이 아닙니다.
- **리뷰는 테스트가 못 보는 것.** 테스트를 통과해도 비밀 값 · 위험 함수 · 테스트 약화 · 구조 위반을 넣을 수 있습니다. 규칙(정규식 · diff 의 더한 줄)으로 빠르게 보고, 규칙 밖의 논리 문제는 LLM 리뷰로 봅니다. 좋은 · 나쁜 diff 12개(그중 하나는 규칙으로 못 잡는 논리 버그)로 규칙 · LLM 리뷰의 정밀도 · 재현율을 잽니다. 에이전트가 쓴 diff 도 같은 리뷰를 거칩니다.
- **해결률과 비용을 함께.** 과제마다 해결 여부 · 깨진 파일을 고쳤는지 · 걸음 · 출력 토큰 · diff 줄 수 · 리뷰 지적 · 시간을 남깁니다. 같은 과제로 모델 · 걸음 상한을 바꿔 비교합니다.
