# 권한 · 감사 · 라이선스 (G3 · G5 · G6)

화면은 `/guardrails/access` 입니다(문서 권한 · 유출 시험 · 감사 로그 · 라이선스 점검).

## G3 권한별 검색

- **사용자 · 그룹**: `.env` 의 `API_USERS=[{"name", "token", "groups", "role"}]`. `API_TOKEN` 은 모든 문서를 보는 관리자 토큰으로 남고, 토큰 없이 쓰면(개인 PC) 로컬 사용자가 관리자입니다. 지금 사용자는 `/api/me`.
- **문서 권한**: 문서 메타 `acl`(그룹 목록). 비어 있으면 모두 공개. 문서 처리 화면(`/docintel/sources#meta`)에서 고치며, `acl` 을 바꾸는 것은 관리자만 됩니다 — 일반 사용자가 자기 권한을 넓히면 이 단계가 무의미해집니다.
- **검색 전에 거름**: 연결 계층 `app/pipeline/search.py` 의 `restrict` 가 사용자 그룹으로 허용 문서를 구해 `doc_ids` 로 바꾸고, 메타 필터(D6) · 화면에서 고른 문서와 겹칩니다. 답변 뒤에 지우면 LLM 이 이미 읽은 뒤라 늦기 때문입니다.
- **허용 문서가 0개면 빈 결과.** 빈 목록을 '제한 없음'으로 읽으면 권한이 없는 사람이 모든 문서를 보게 됩니다(처음 구현에서 실제로 그렇게 될 뻔해 테스트로 고정).
- 관리자만 `acl_groups` 로 '이 그룹으로 검색해 보기'를 할 수 있고, 일반 사용자의 요청 값은 자기 그룹으로 덮어씁니다.

## G5 감사 로그

- 요청 기록(`traces`, 평가 · 관측 E3 와 같은 표)에 사용자 · 그룹 · 질문 · 근거 문서 · 답 · 검사 결과를 남깁니다.
- **해시 체인**: 기록마다 앞 기록의 해시 + 자기 내용으로 해시를 만듭니다(`app/core/tracing.py`). 중간 기록을 고치거나 지우면 그 뒤 해시가 맞지 않아 무결성 검사가 처음 깨진 기록을 알려 줍니다. 기록을 쓸 때 잠금을 걸어 두 요청이 같은 '앞 해시'를 쓰지 않게 했습니다.
- 해시를 만들기 전에 칸 기본값(빈 목록 · 빈 글)을 채웁니다 — 기본값을 DB 가 나중에 채우면 저장된 값과 해시 계산 값이 달라 '고쳐짐'으로 잘못 나왔습니다(구현 중 발견한 버그).
- 목록 행마다 근거 문서 이름(최대 3개, 나머지는 '외 n개')을 보여 줍니다 — 감사의 핵심 질문이 '무엇을 근거로 나갔나'라서.
- 조회 · CSV 내보내기는 관리자만. 보관 기간(`TRACE_RETENTION_DAYS`)이 지난 기록은 앱 안 주기 작업이 하루 한 번 지우고, 무결성은 남은 첫 기록부터 다시 검사합니다.
- 실측: 2026-10-21 기록 154건 무결성 검사 통과(깨진 기록 0).

## G6 라이선스 · 출처

자료는 문서 메타의 출처 · 라이선스(공개 자료 가져오기가 남김), 임베딩 · 리랭커는 모델 카탈로그의 라이선스, LLM 은 이름으로 판정합니다.

| 판정 | 뜻 |
|---|---|
| ok | 상업 사용에 걸림 없음(MIT · Apache-2.0 · 공공누리 1유형 · openrail 등) |
| warn | 조건 확인 필요(비상업 · 모델 카드 확인) |
| unknown | 기록 없음 — 직접 올린 문서 |
| block | 사용 금지 표시 |

실측(2026-10-21): 법률 컬렉션 + KURE 인덱스 + gemma-4-e4b → 자료 2묶음 ok(판례 openrail · 법령 공공누리 1유형), 임베딩 MIT ok, LLM warn(모델 카드 확인). 공공문서 컬렉션은 직접 올린 문서라 자료가 unknown — 출처를 남기지 않은 자료가 서비스에 들어가는 것을 이 점검이 드러냅니다.
