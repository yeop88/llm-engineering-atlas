# G1 · 입력 방어 (프롬프트 인젝션) (Prompt injection defense)

**상태: ⬜ 예정** — 사용자 입력과 근거 문서 속에 숨은 지시가 LLM 을 조종하지 못하게 막는다

## 원리

프롬프트 인젝션은 '이전 지시를 무시하고 …' 같은 문장으로 LLM 의 동작을 바꾸는 공격입니다. 사용자 입력뿐 아니라 업로드된 문서 · 웹 페이지(간접 인젝션)로도 들어옵니다. 지시와 데이터를 분리하고, 의심 문장을 감지하고, 도구 권한을 줄여 막습니다.

## 왜 하는가

RAG 는 문서를 그대로 LLM 에 넣고, 에이전트는 도구를 실행합니다. 문서 하나에 숨은 지시로 다른 문서 내용이 새거나 도구가 오용될 수 있습니다.

## 어떻게 (이 앱에서)

- (있음) 에이전트 계산 도구는 eval 없이 산술식만, Text2Cypher(예정)는 읽기 전용으로 설계
- (예정) 근거를 '데이터'로 감싸는 프롬프트 구조, 의심 문장 감지(규칙 + 분류기), 도구별 허용 범위

## 화면

- 아직 테스트 화면이 없습니다. 단계 소개는 앱의 `/stages/gr_injection` 에서 볼 수 있습니다.
