# 벤치마크 시각화

벤치마크 결과(새로 실행했거나 "이전 벤치마크 → 보기"로 연 결과)의 결과 표 아래에 차트가 자동으로 그려집니다. 표가 모든 값의 원본이고, 차트는 패턴을 빠르게 읽기 위한 보조 수단입니다.

## 차트 종류

| 차트 | 대상 | 읽는 법 |
|---|---|---|
| **성능 vs 속도** (버블) | 검색·STS | 가로 = 처리 속도(로그 축), 세로 = 대표 지표, 원 크기 = 파라미터 수. 파란 원 = 파레토 최적(자기보다 빠르면서 더 정확한 모델이 없음, 이름 표시). 회색 원은 마우스를 올리면 이름이 보임 |
| **Recall@k** (선) | 검색 | 상위 1·3·5·10개 안에 정답이 들어온 비율. 왼쪽(@1)이 높을수록 1위 정확도가 좋음. 범례를 누르면 모델 숨김 |
| **언어 그룹별** (가로 막대) | 검색 (쿼리에 `lang`이 있을 때) | 모델별 ko / en / ko→en / en→ko nDCG@10. 짧은 막대가 약점 |
| **모델 프로필** (레이더) | 검색 | 최대 3개 모델 선택. nDCG@10, Recall@1, MRR@10, 교차언어, STS Spearman, 상대 속도를 0~100%로 비교. STS 축은 가장 최근 STS 데이터셋 실행들을 합쳐 모델별 최신 값을 가져옴 |
| **정답 점수 vs 코사인** (작은 산점도 여러 개) | STS | 모델당 하나. 점이 왼쪽 아래 → 오른쪽 위로 가지런할수록 사람 판단과 일치. 점에 마우스를 올리면 문장쌍 표시 |
| **쿼리별 첫 정답 순위** (표 색칠) | 검색 | 초록 = 1위, 빨강(굵게) = Top-3 밖. 칸에 마우스를 올리면 Top-5 문서 |

| **차원별 성능** (선, Matryoshka) | 검색·STS (벤치마크에서 "차원 스윕"을 켰을 때) | 임베딩을 앞에서부터 잘라 차원을 줄였을 때의 지표. "절대값"과 "전체 차원 대비 %"를 전환할 수 있음. ◆ 모양 = MRL로 학습되지 않은 모델. 툴팁에 벡터당 저장 용량(float32) 표시. "표로 보기"로 같은 값을 표로 확인 |

## 임베딩 지도 (플레이그라운드 → 임베딩 지도 탭)

문장들을 모델로 임베딩한 뒤 2차원으로 줄여 점으로 찍습니다. 최대 3개 모델을 나란히 비교합니다.

- **입력**: 한 줄에 한 문장. `ko: 문장`처럼 `그룹: 문장` 형식이면 그룹별로 색이 다릅니다. 그룹은 3개까지 색으로, 4번째부터는 회색 + 모양으로 구분합니다.
- **투영 방법**: PCA(빠르고 전체 구조 유지, 두 축이 설명하는 분산 비율 표시) / t-SNE(가까운 것끼리 뭉치는 모양 강조, 문장 10개 이상).
- **의미 쌍 연결**: 그룹이 정확히 2개이고 개수가 같으면 i번째끼리(예: 한국어 i번째 ↔ 영어 i번째) 같은 뜻의 쌍으로 보고 회색 선으로 잇습니다. 선이 짧을수록 두 언어가 같은 자리에 정렬된 것입니다.
- **정렬도 표** (원래 차원 기준, 2D로 줄이기 전):
  - 의미 쌍 코사인: 같은 뜻 문장끼리의 평균 유사도
  - 다른 문장과 코사인: 뜻이 다른 문장과의 평균 유사도
  - **차이**: 위 둘의 차이. 클수록 "같은 뜻은 가깝고 다른 뜻은 멀다". 대표 지표입니다.
  - 짝 찾기 정확도: 각 문장에서 가장 가까운 상대 언어 문장이 실제 짝인 비율
- 축 값 자체에는 의미가 없습니다. 2D로 줄이면 정보가 손실되므로(PCA는 보통 30% 안팎만 설명) 정확한 비교는 정렬도 표를 보세요.

### 실측 예 (기본 예시 문장: 한/영 번역쌍 8개)

| 모델 | 쌍 코사인 | 다른 문장 | 차이 | 짝 찾기 |
|---|---|---|---|---|
| BAAI/bge-m3 | 0.893 | 0.423 | **0.470** | 100% / 100% |
| google/embeddinggemma-2 | 0.869 | 0.606 | 0.263 | 100% / 100% |
| intfloat/multilingual-e5-large-instruct | 0.930 | 0.730 | 0.201 | 100% / 100% |

mE5-instruct는 쌍 유사도가 가장 높지만 뜻이 다른 문장끼리도 0.73으로 높게 나와 구분 폭이 가장 좁습니다. 코사인 값 하나만 보면 안 되는 이유입니다.

## 설계 원칙

- **색은 모델을 따라갑니다.** 한 결과 안에서 모델 → 색이 고정되고(결과 목록 순서), 범례로 숨겨도 다른 모델 색이 바뀌지 않습니다. 9번째 모델부터는 회색입니다.
- **범주 색 8개**는 라이트(`#ffffff`)·다크(`#181c24`) 배경 각각에서 색각이상 구분(인접 ΔE ≥ 8)과 일반 시각 구분(ΔE ≥ 15) 검사를 통과했습니다. 라이트 모드의 연한 색 3개(청록·노랑·분홍)는 대비가 3:1 미만이라 범례·라벨·표를 함께 둡니다.
- 서로 겹치는 차트(레이더)는 모든 색 쌍이 구분돼야 하므로 3개까지만 비교합니다. STS 산점도는 모델 수와 상관없이 읽히도록 작은 차트 여러 개로 나눴습니다.
- 축은 항상 하나입니다(이중 축 없음). 선 2px, 점 지름 8px 이상에 배경색 테두리, 막대 끝 4px 둥글림, 실선 격자입니다.
- OS 다크/라이트 전환 시 새 색으로 다시 그립니다. 색 값은 `static/css/style.css`의 `--series-1`~`--series-8`, `--chart-grid`, `--chart-axis`입니다.

## 이력 추세 · 내보내기 · 대시보드

- **이력 추세** (벤치마크 화면 아래): 위에서 고른 데이터셋으로 실행한 벤치마크들의 모델별 대표 지표를 실행 순서대로 잇습니다. 라이브러리(transformers 등)나 모델을 업데이트한 뒤 결과가 달라졌는지 확인할 때 씁니다. 차원을 줄여(`truncate_dim`) 실행한 결과는 비교할 수 없어 제외합니다. 실행이 2건 이상일 때 표시됩니다.
- **내보내기** (결과 화면 오른쪽 위):
  - **HTML 리포트**: 결과 표와 차트(이미지)를 파일 하나에 담습니다. 인터넷 없이 브라우저로 열 수 있고, 실행 환경(Python·디바이스·라이브러리 버전)이 함께 기록됩니다. 차트는 내보낸 순간의 테마(라이트/다크)로 고정됩니다.
  - **JSON**: 원본 결과 데이터 (다른 도구로 분석할 때).
  - **PNG**: 각 차트 카드 제목 옆 버튼. 작은 다중 차트(STS)는 한 장으로 합쳐 저장합니다.
- **대시보드**: 메모리 사용량(이 앱 프로세스 / 시스템 전체, 5초 간격 최근 10분)과 가장 최근 벤치마크의 모델별 대표 지표 막대를 보여 줍니다. 메모리 기록은 서버가 켜져 있는 동안만 쌓입니다.

## 라이브러리

- **Chart.js 4.5.1**(2026-10 기준 최신 안정 버전)을 cdnjs에서 SRI 무결성 해시와 함께 불러옵니다(`templates/benchmark.html`).
- 실제 차트 코드는 `static/js/charts.js`(Chart.js를 사용하는 이 프로젝트의 파일)에 있습니다.
- CDN에 접속할 수 없으면 차트 대신 안내 문구가 나오고, 결과 표는 그대로 쓸 수 있습니다.
- 버전을 올릴 때는 새 파일의 SRI 해시를 다시 계산해 `integrity` 값을 바꿉니다.

  ```bash
  curl -sL https://cdnjs.cloudflare.com/ajax/libs/Chart.js/<버전>/chart.umd.min.js | openssl dgst -sha384 -binary | openssl base64 -A
  ```
