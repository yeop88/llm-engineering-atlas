# 문서 검색 (RAG)

임베딩 모델을 실제 업무 문서 검색에 쓰기 전에, **청킹 전략 × 임베딩 모델 × 벡터 DB × 검색 방식 × 리랭커** 조합을 직접 만들어 비교하는 기능입니다. 메뉴의 **문서 검색**에서 시작합니다.

```
문서 업로드 → ② 청크 세트(청킹 전략) → ③ 벡터 인덱스(임베딩 모델 + 벡터 DB) → ④ 검색 비교(의미/BM25/하이브리드 + 리랭커)
```

## 1. 컬렉션과 문서

- **컬렉션**은 문서 묶음입니다. 도메인(사내 문서 · 법률 · 고객·AS 문의 · 제품·매뉴얼 등)별로 만듭니다. 법률 도메인은 청킹 기본값이 "법률 구조"로 바뀝니다.
- 지원 형식: **PDF · DOCX · HWP(5.x) · HWPX** · TXT · MD · HTML · CSV · TSV · JSON · JSONL (파일당 기본 100MB, `MAX_UPLOAD_MB`)
  - HWP 는 바이너리 구조를 직접 읽습니다(외부 프로그램 불필요). 같은 문서 기준으로 PDF 보다 깨끗하게(목차 점선 등 잡음 없음), 약 100배 빠르게 추출됩니다.
  - 배포용(보호) HWP 는 본문이 암호화되어 미리보기 텍스트만 읽습니다. 암호 문서는 지원하지 않습니다.
  - 스캔 PDF 는 텍스트가 없어 OCR 이 필요합니다(업로드 시 경고).
  - 표는 셀을 ` | ` 로 이어 텍스트로 넣습니다(DOCX). HWP·HWPX 표는 셀이 줄 단위로 들어갑니다.
- 같은 내용의 파일(SHA-256 동일)은 자동으로 건너뜁니다.
- 원문은 페이지(PDF 쪽 / HWP 구역) 단위로 보관하므로, 청킹 전략을 바꿔 언제든 다시 나눌 수 있습니다.

## 2. 청크 세트 (청킹 전략)

| 방법 | 동작 | 언제 |
|---|---|---|
| **재귀 분할** (기본) | 문단 → 줄 → 문장 → 단어 순으로 큰 경계부터 잘라 길이에 맞춤 | 대부분의 문서 |
| **고정 길이** | 정해진 글자 수 + 겹침, 공백에서 끊음 | 구조 없는 텍스트(로그·OCR) |
| **문장 단위** | Kiwi 형태소 분석기로 한국어 문장을 나눈 뒤 묶음, 겹침은 문장 수 | 문장이 잘리면 안 되는 문서 |
| **법률 구조** | 법령은 조문(제N조, 제N조의N)·항(①②) 단위, 판결문은 【주문】【이유】【판시사항】 등 구획 단위. 각 청크에 소속 조문 제목 기록 | 법령 · 판례 · 계약서 |
| **페이지** | PDF 쪽 / HWP 구역 단위(너무 길면 재귀 분할) | 쪽 번호 인용이 중요한 문서 |

- 크기·겹침 단위는 **글자 수**입니다(한국어는 대략 1~1.5글자 ≈ 1토큰). 임베딩 모델의 최대 입력 길이보다 작게 잡으세요.
- **"임베딩할 때 문서 제목·조문 제목 붙이기"**를 켜면(기본) 인덱싱할 때 `문서 제목 · 조문 제목\n청크` 형태로 맥락을 붙여 임베딩합니다. 청크 원문은 그대로 보관합니다.
- **미리보기**로 청크 수, 길이 분포(히스토그램), 예시를 보고 정한 뒤 만듭니다. 만들 때 각 청크의 형태소(BM25 용)도 함께 저장합니다.
- 청크 세트를 만든 뒤 문서를 추가·삭제하면 **"문서 변경됨"** 표시가 붙습니다. 새 문서를 검색하려면 청크 세트를 다시 만드세요(문서 삭제는 자동 반영).

## 3. 벡터 인덱스

청크 세트 하나를 **임베딩 모델 + 벡터 DB (+ Matryoshka 차원)** 로 인코딩해 저장합니다. 같은 청크 세트로 여러 인덱스를 만들어 비교할 수 있습니다.

| 벡터 DB | 설정 | 특징 |
|---|---|---|
| **Qdrant** (기본) | `QDRANT_URL` 없으면 서버 없이 로컬 파일 모드(`data/qdrant`), 있으면 서버 | 필터·대규모·운영에 강함. 서버 대시보드 `http://localhost:6333/dashboard` |
| **PostgreSQL pgvector** | `PGVECTOR_URL` | ≤2000차원 `vector`+HNSW, ≤4000차원 `halfvec`+HNSW, 그 이상은 인덱스 없이 정확 검색(자동 선택). 문서 필터 시 반복 스캔(pgvector 0.8+) |
| **MariaDB VECTOR** | `MARIADB_URL` (11.7+) | `VECTOR(n)` + `VECTOR INDEX ... DISTANCE=cosine`. 기존 MariaDB/MySQL 인프라를 쓰는 경우 |

```bash
docker compose up -d                                          # Qdrant 서버 (선택 — 없어도 로컬 모드로 동작)
docker compose --profile pgvector --profile mariadb up -d     # pgvector(5433), MariaDB(3307) 추가
```

- 구축은 백그라운드 작업이며 진행률과 남은 시간을 보여 줍니다. 처음 쓰는 모델은 다운로드부터 합니다.
- 모든 저장소는 같은 점수(코사인 유사도)를 돌려주므로 서로 비교할 수 있습니다.
- 문서를 지우면 해당 청크의 벡터도 모든 인덱스에서 지웁니다.

## 4. 검색 비교

최대 4개 설정을 나란히 실행합니다. 설정은 브라우저에 컬렉션별로 저장됩니다.

| 항목 | 설명 |
|---|---|
| **방식** | 의미 검색(벡터) / BM25(형태소 키워드) / **하이브리드**(둘을 합침) |
| **합치기** | **RRF**(순위 기반, 점수 척도가 달라도 안정적 — 권장) / 가중합(점수 정규화 후 `α·의미 + (1−α)·BM25`) |
| **검색 후보** | 각 방식에서 가져올 후보 수(기본 50) |
| **리랭커** | 상위 후보(기본 30)를 Cross-Encoder 로 질의와 함께 다시 읽어 재정렬. 느리지만 정확도가 크게 오름 |
| **결과 수** | 최종으로 보여 줄 개수 |

결과마다 의미·BM25 순위와 점수, 리랭크 전 순위, 문서·쪽·조문 제목, 질의 형태소 하이라이트, 단계별 소요 시간(모델 로드 · 질의 임베딩 · 벡터 검색 · BM25 · 리랭킹)이 나옵니다.

### BM25 (한국어)

[Kiwi](https://github.com/bab2min/kiwipiepy) 형태소 분석으로 명사·동사/형용사 어간·어근·외국어·숫자만 남겨 색인합니다("공문서는 한글로 작성하여야" → `공문서 한글 작성`). 조사·어미 차이에 강하고, 법령 조문 번호나 제품 모델명처럼 **정확히 일치해야 하는 키워드**를 의미 검색이 놓칠 때 보완합니다.

### 리랭커

모델 화면의 종류 필터에서 "리랭커"로 볼 수 있습니다(BGE Reranker v2 M3, 한국어 파인튜닝판, Qwen3-Reranker 0.6B/4B, mxbai-rerank-v2, Nemotron Rerank 등). 입력 길이는 기본 1024토큰으로 제한합니다(`RERANKER_MAX_LENGTH`).

## 추천 출발점

| 도메인 | 청킹 | 검색 |
|---|---|---|
| 사내 문서 · 매뉴얼 | 재귀 600~800자, 겹침 80~100 | 하이브리드(RRF) + 리랭커 |
| 법령 · 판례 · 계약서 | 법률 구조 800자, 제목 포함 | 하이브리드(RRF) — 조문 번호·법률 용어는 BM25 가 강함 + 리랭커 |
| 고객 · AS 문의 / FAQ | 재귀 400~500자 | 의미 검색 또는 하이브리드, 짧은 질의엔 리랭커 효과가 큼 |

정답이 있는 평가셋으로 조합을 수치 비교하는 기능은 다음 단계(평가 고도화)에서 추가합니다.
