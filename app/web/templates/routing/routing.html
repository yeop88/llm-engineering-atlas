라우팅 테스트

질문의 난이도를 먼저 판단해 쉬운 질문은 빠른 경로, 어려운 질문은 전체 경로로 보냅니다. 목표는 "항상 전체 경로"의 품질을 지키면서 비용(지연)을 줄이는 것입니다. 7 소형 모델 · 8 에이전트가 아직 없어, 지금은 두 경로가 같은 LLM 을 쓰고 검색 단계(향상 · 리랭커)가 다릅니다.

경로 설정

빠른 경로 (쉬운 질문)
1 임베딩 → 2 검색 → 답변. 향상 · 리랭커 없음.
전체 경로 (어려운 질문)
라우터:

질문 하나 판단

평가 세트로 라우터 비교

질문마다 두 경로를 한 번씩 실행한 뒤, 각 라우터가 고른 경로의 결과로 품질 · 지연을 계산합니다(라우터마다 다시 실행하지 않음). 오라클 = 질문마다 실제로 나았던 경로를 고른 경우로, 라우팅으로 얻을 수 있는 상한입니다. 답변을 켜면 질문당 두 번 답하므로 로컬 LLM 으로 질문당 1분 안팎이 걸립니다.

학습 라우터

위 비교의 기록(질문마다 두 경로 결과)으로 '전체 경로가 실제로 나았던 질문'을 배웁니다. 입력 = 질문 임베딩 + 검색 확신도 + 질문 형태 신호, 모델 = 로지스틱 회귀. 채점은 교차검증(그 질문을 빼고 학습한 모델의 예측)이라 같은 기록의 다른 라우터와 공정하게 비교됩니다. 질문이 적으면(수십 개) 결과가 크게 흔들립니다.
